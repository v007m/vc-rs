`type: oauth2ClientCredentials` posts to the token endpoint with the client's own credentials and sends the token it gets as `Authorization: Bearer`. Use it for service-to-service calls.

```yaml title="vibranium.config.yaml (excerpt)"
auth:
  - id: labClient
    type: oauth2ClientCredentials
    tokenUrl: ${var.labUrl}/token
    clientId: ci-runner
    clientSecret: ${secret.LAB_CLIENT_SECRET}
    scopes: [items:read, items:write]
    audience: https://lab.example
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `type` | `oauth2ClientCredentials` | — | yes | |
| `tokenUrl` | URL template | — | yes | |
| `clientId` | text | — | yes | |
| `clientSecret` | text or template | — | no | Without it, the client is public |
| `scopes` | list of text | — | no | Sent space-separated as `scope` |
| `audience` | text | — | no | Sent as `audience` |
| `refreshBefore` | duration | `1m` | no | Capped at half the token's lifetime |
| `refreshOn` | list of status codes | `[401]` | no | |
| `vars` | map | — | no | |

## Examples

With a secret, the client goes in HTTP Basic. The token request the server received:

```console
POST /token
authorization: Basic Y2ktcnVubmVyOmNzLTMxMzM3
grant_type=client_credentials&scope=items%3Aread%20items%3Awrite&audience=https%3A%2F%2Flab.example
```

A public client has no secret. Its ID goes in the form instead:

```yaml
auth:
  - id: labPublicClient
    type: oauth2ClientCredentials
    tokenUrl: ${var.labUrl}/token
    clientId: cli-app
```

```console
POST /token
grant_type=client_credentials&client_id=cli-app
```

Two tests that use the same definition share one token. The server saw one `POST /token` for both.

A short-lived token is fetched again before it expires. This endpoint returns tokens that last 4 seconds; the default `refreshBefore` of `1m` is capped at half of that, so a call 2.5 seconds later gets a fresh token:

```yaml
auth:
  - id: labShortClient
    type: oauth2ClientCredentials
    tokenUrl: ${var.labUrl}/token?ttl=4
    clientId: ci-runner
    clientSecret: ${secret.LAB_CLIENT_SECRET}
```

With `refreshBefore: 1s`, the same token is reused at 2.5 seconds.

## How it behaves

- The token is fetched before the first request that needs it, then shared by every test that uses the same definition and vars.
- The token's lifetime comes from the response's `expires_in`.
- A refused token request (400, 401, 403) is kept for the run, so tests don't each retry it. A failure that may pass (network, timeout, 429, 5xx) is dropped, and the next request tries again.
- The V5114 message names the endpoint's status, never its body.

## Common errors

- [V5114](/vc-rs/reference/diagnostics/v5114/): the token endpoint refused the request.
