An auth definition says how to get credentials. You write it once under `auth` in `vibranium.config.yaml` and use it by ID on an api file, an api, a test, a step or an action.

```yaml title="vibranium.config.yaml (excerpt)"
auth:
  - id: labBearer
    type: bearer
    token: ${secret.LAB_TOKEN}
```

```yaml title="services/lab/lab.api.yaml (excerpt)"
id: lab
baseUrl: ${var.labUrl}
auth: labBearer
```

## Auth types

| `type` | Sends | Page |
| --- | --- | --- |
| `basic` | `Authorization: Basic …` | [basic](/vc-rs/reference/auth/basic/) |
| `bearer` | `Authorization: Bearer <token>`, a fixed token | [bearer](/vc-rs/reference/auth/bearer/) |
| `apiKey` | a key in a header or the query | [apiKey](/vc-rs/reference/auth/api-key/) |
| `oauth2ClientCredentials` | a token from the client credentials grant | [oauth2ClientCredentials](/vc-rs/reference/auth/oauth2-client-credentials/) |
| `oauth2Password` | a token from the password grant | [oauth2Password](/vc-rs/reference/auth/oauth2-password/) |
| `oauth2AuthorizationCode` | a token after one browser sign-in | [oauth2AuthorizationCode](/vc-rs/reference/auth/oauth2-authorization-code/) |
| `oauth2Refresh` | a token from a long-lived refresh token | [oauth2Refresh](/vc-rs/reference/auth/oauth2-refresh/) |
| `flow` | whatever your own login steps produce | [flow](/vc-rs/reference/auth/flow/) |
| `plugin` | whatever an auth plugin returns | [plugin](/vc-rs/reference/auth/plugin/) |

## Fields every definition has

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `id` | camelCase text | — | yes | What `auth:` names |
| `name` | text | — | no | Shown in output |
| `type` | one of the types above | — | yes | |
| `vars` | map | — | no | Defaults for the templates in this definition |
| `refreshBefore` | duration | `1m` | no | Fetch again this long before expiry, capped at half the lifetime |
| `refreshOn` | list of status codes | `[401]` | no | Fetch again once and retry when a response has one of these |

## Examples

Use a different auth for one test:

```yaml
tests:
  - id: sendsBasic
    call: lab#whoami
    auth: labBasic
```

Send no auth at all:

```yaml
  - id: sendsNoAuth
    call: lab#whoami
    auth: none
```

## How it behaves

- Values that change between environments come from vars, so profiles switch them: one definition serves every profile.
- Tokens are fetched lazily, before the first request that needs them, and shared by every test that uses the same definition and vars.
- Credentials are masked in all output from the moment they arrive. See [Redaction](/vc-rs/reference/auth/redaction/).
- When credentials cannot be obtained, every call that needs them fails with V5114.

## Common errors

- [V5114](/vc-rs/reference/diagnostics/v5114/): credentials could not be obtained.
- [V2106](/vc-rs/reference/diagnostics/v2106/): a `${secret.X}` is not declared in `.env.schema`.
- [V2302](/vc-rs/reference/diagnostics/v2302/): a field has a value its type does not accept.
