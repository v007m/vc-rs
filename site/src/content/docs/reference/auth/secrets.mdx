A secret is a value you read as `${secret.NAME}`. Its name is declared in `.env.schema`, its value comes from a provider, and it is masked everywhere vc prints or stores it.

```text title=".env.schema"
# The secret names this project uses, one NAME= line each, never their values.
LAB_PASSWORD=
LAB_TOKEN=
LAB_CLIENT_SECRET=
```

```yaml title="vibranium.config.yaml (excerpt)"
auth:
  - id: labBearer
    type: bearer
    token: ${secret.LAB_TOKEN}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `secrets.provider` | `env` or `varlock` | `env` | no | Where the values come from |
| `secrets.schema` | path | `.env.schema` | no | The file that declares the names |

`.env.schema` holds one `NAME=` line per secret. Comments and `# @…` annotations are allowed. Commit it; it holds no values.

| Provider | Values come from |
| --- | --- |
| `env` | The process environment, then the project's `.env` for names the environment does not set |
| `varlock` | `varlock load`, which reads Varlock's own providers (1Password, Vault, AWS, GCP, Azure, Bitwarden, Infisical and others) |

## Examples

Keep values in `.env` on your machine and in the environment on CI. Do not commit `.env`.

```text title=".env"
LAB_TOKEN=tok-static-9f2c
```

The process environment beats `.env`. With `LAB_TOKEN=from-process-env` set in the shell, the server received:

```console
GET /whoami  authorization: Bearer from-process-env
```

`vc check` catches a misspelled name and offers a certain fix:

```console
error[V2106]: `${secret.LAB_TOKN}` is not declared in `.env.schema`
 --> services/lab/secrets.test.yaml:6:16
  |
6 |       x-token: ${secret.LAB_TOKN}
  |                ^^^^^^^^^^^^^^^^^^ LAB_TOKN is not in .env.schema
  = help: add the line `LAB_TOKN=` to `.env.schema` at the project root, or fix the name
  = help: did you mean `LAB_TOKEN`?
  = fix: Replace with LAB_TOKEN (certain)
```

Reading a declared secret through `env` is an error, because it would skip masking:

```console
error[V2107]: `${env.LAB_TOKEN}` reads a secret that `.env.schema` declares
  --> services/lab/secrets.test.yaml:10:16
   |
10 |       x-token: ${env.LAB_TOKEN}
   |                ^^^^^^^^^^^^^^^^ LAB_TOKEN is a secret
   = note: a declared secret is reachable only as `${secret.X}`, so it is masked everywhere
   = help: write `${secret.LAB_TOKEN}`
   = fix: Replace with secret.LAB_TOKEN (certain)
```

A declared secret that the selected tests read, with no value (not set, or blank), stops the run with V5114 before any request is sent. A secret nothing selected reads, or one marked `# @optional` in `.env.schema`, may be unset; a test that reads an unset or blank optional secret fails with V5114 when it renders. When the selection runs code (a `function:` action, a request hook, a `function` check or a `redact` `function` rule) or the project loads a plugin, every declared secret counts as read, since code can call `secret()` with any name. The message names only the secrets that have no value:

```console
error: secrets: V5114: the declared secret `LAB_UNSET` has no value
  = help: set it in the environment or the project's `.env` (or in the `secrets.provider`), or remove it from `.env.schema`
```

`vc call` (for the secrets its api reads) and `vc load` stop the same way.

Use Varlock. It must be on `PATH`:

```yaml title="vibranium.config.yaml (excerpt)"
secrets:
  provider: varlock
```

Without it, the run stops before any test:

```console
error: secrets: the varlock secrets provider is unavailable: `varlock` is not on PATH
```

Varlock is told the run's profile as `VC_PROFILE`: the last `--profile` given, else the last `default: true` one. vc never passes `--env`. Point Varlock's `@currentEnv` at it, and `vc run --profile staging` loads `.env.staging` beside the schema:

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
  - id: staging
secrets:
  provider: varlock
auth:
  - id: labBearer
    type: bearer
    token: ${secret.LAB_TOKEN}
```

```dotenv title=".env.schema"
# @currentEnv=$VC_PROFILE
# ---
# Varlock's environment flag. Used when VC_PROFILE is unset.
VC_PROFILE=dev
LAB_TOKEN=
```

The `VC_PROFILE` line is Varlock's environment flag, not a secret: vc does not load, mask or require it, and `${secret.VC_PROFILE}` is [V2106](/vc-rs/reference/diagnostics/v2106/).

## How it behaves

- Only names in `.env.schema` can be read as `${secret.X}`, and a declared name cannot be read as `${env.X}`.
- Values of four characters or more are masked as `••••` wherever they appear: output, history and reports. A shorter value is shown as it is. See [Redaction](/vc-rs/reference/auth/redaction/).
- A [`command:` action](/vc-rs/reference/lifecycle/command/) gets the `.env` values in its environment. A declared secret in its output is masked; a value in `.env` that is not declared is not.
- A plugin gets a secret only when you write it in that plugin's `config`. See [plugin](/vc-rs/reference/auth/plugin/).

## Common errors

- [V2106](/vc-rs/reference/diagnostics/v2106/): the name is not declared in `.env.schema`.
- [V2107](/vc-rs/reference/diagnostics/v2107/): a declared secret is read as `${env.X}`.
- [V5111](/vc-rs/reference/diagnostics/v5111/): a declared secret has no value at run time.
