`vc load <scenarioId>` runs one load file: shared setup once, a live line each second, then a summary and an exit code.

```console
$ vc load sample.smoke
```

## Syntax

```console
$ vc load --help
Runs a load scenario with live metrics

Usage: vc load [OPTIONS] <SCENARIO>

Arguments:
  <SCENARIO>  The scenario to run: its load file's ID (`checkout.peak` for `load/checkout/peak.load.yaml`)

Options:
      --profile <IDS>    The active profiles, as a comma list or repeated; later ones win
      --project <DIR>    The project to work on: this folder or the nearest one above it with a `vibranium.config.yaml`. Relative paths and selectors then start at the project root
      --set <KEY=VALUE>  Sets one config value (`defaults.timeout=5s`, `vars.userId=7`), over every other config layer (D129)
      --json             Prints the final report as JSON on stdout, with no live line
  -h, --help             Print help
```

| Exit code | Meaning |
| --- | --- |
| 0 | Finished within every threshold |
| 1 | Blocked: a shared action (`beforeRun` or `beforeAll`) failed |
| 2 | Nothing ran: the project has errors, no scenario has that ID, or no mix test has a weight above 0 |
| 3 | A threshold was breached over the whole run, aborted or not |
| 130 | Cancelled |


Each live line is: seconds since the start, users, `rps` over the last 3 seconds, `p50`, `p95` and `p99` over the last 10 seconds, the error count, and `breaching:` when a threshold is breached. The summary covers the whole run.

### A breach: exit 3

```console
$ vc load sample.strict; echo "exit $?"
...
sample.strict — Too strict on purpose · finished after 5 s · 2315 iterations · 463.0 rps · 0 errors
latency p50 2.7 ms · p90 6.0 ms · p95 8.2 ms · p99 15.6 ms · max 35.7 ms
breached p99 at 15.615 ms (lt 1 ms)
breached sample.basics#getsCreatedUser: p95 at 11.215 ms (lt 2 ms)
exit 3
```

### An unknown scenario: exit 2

```console
$ vc load nope.nope; echo "exit $?"
error: no load scenario has the ID `nope.nope`
  = help: the scenarios are: sample.abort, sample.checks, sample.full, sample.lifecycle, sample.smoke, sample.strict
exit 2
```

### In CI

```yaml title=".github/workflows/load.yml"
- run: vc load checkout.peak --profile staging --json > load-report.json
```

The step fails on any exit code other than 0, so a breach (3) fails the job.

## How it behaves

- `vc load` checks the whole project first. Any error, even in another file, stops it before a request is sent: `error: the project has 1 error(s); nothing ran`, exit code 2.
- `--profile` and `--set` work as for `vc run`.
- `vc load` has no `--seed` flag; the seed it used is in the JSON report. See [Generation and seeds](/vc-rs/reference/data/seeds/).
- Every load run gets a run ID (`runId`), like a functional run.
