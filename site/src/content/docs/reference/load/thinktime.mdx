`thinkTime` is how long each user waits after one iteration before starting the next, like a person reading a page.

```yaml
thinkTime: 100ms          # fixed
```

```yaml
thinkTime:                # random, between the two
  min: 50ms
  max: 200ms
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `thinkTime` | duration, or a map of `min` and `max` | `0s` | no | `0s` means users start the next iteration at once. |
| `min` | duration | — | with `max` | Shortest pause; no longer than `max`. |
| `max` | duration | — | with `min` | Longest pause. |

## Examples

Think time sets how hard a few users push. Two real runs against the demo:

### No think time

`sample.strict` has no `thinkTime`. Three users made 2315 iterations in 5 seconds:

```console
    4s  3 users  417 rps  p50 2 ms  p95 8 ms  p99 15 ms  0 errors  breaching: p99, sample.basics#getsCreatedUser: p95
...
sample.strict — Too strict on purpose · finished after 5 s · 2315 iterations · 463.0 rps · 0 errors
```

### A random pause

`sample.smoke` has `thinkTime` from `50ms` to `200ms`. Five users made about 20 iterations a second:

```console
    6s  5 users  20 rps  p50 3 ms  p95 6 ms  p99 8 ms  0 errors
...
sample.smoke — Sample smoke load · finished after 10 s · 198 iterations · 19.8 rps · 0 errors
```

### A fixed pause

```yaml title="load/sample/checks.load.yaml (excerpt)"
thinkTime: 100ms
```

## How it behaves

- The pause comes after each iteration and is not part of any latency metric.
- With think time, `rps` is roughly users ÷ (think time + iteration time). Raise users, not lower think time, to model more people.
- A `min` longer than `max` is an error (`V2302`).
