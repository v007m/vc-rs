`secrets` says where `${secret.NAME}` values come from. Names are declared in `.env.schema`; values never go in a committed file.

```yaml title="vibranium.config.yaml"
secrets:
  provider: env
  schema: .env.schema
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `secrets.provider` | `env` or `varlock` | `env` | no | `env` reads the process environment, then `.env`. `varlock` asks the `varlock` tool. |
| `secrets.schema` | path | `.env.schema` | no | The file that declares secret names. See [.env.schema](/vc-rs/reference/config/env-schema/). |

## Examples

Declare the name, use it, and give it a value:

```sh title=".env.schema"
API_TOKEN=
```

```yaml title="services/slow/slow.api.yaml"
  - id: hdr
    path: /hdr
    headers:
      x-token: ${secret.API_TOKEN}
```

```sh title=".env"
API_TOKEN=s3cr3t-value-42
```

The value is masked wherever `vc` prints it:

```console
$ vc call slow#hdr
200 OK · 5 ms · api expect passed
{
  "body": "",
  "headers": {
    ...
    "x-token": "••••"
  },
  ...
}
```

The process environment beats `.env`. Here the echo endpoint returns the first four characters of the token it got:

```console
$ API_TOKEN=from-shell vc call slow#hdr
  "tokenStartsWith": "from"
```

With no value anywhere, the call fails before it is sent:

```console
$ vc call slow#hdr
✗ `secret.API_TOKEN` is missing: `secret` is {}
```

In a run, each test that needs it fails:

```console
$ vc run slow.hdr
✕ slow.hdr#sendsDefaultHeaders                                   38ms
  error[V5111]: `secret.API_TOKEN` is missing: `secret` is {}
     = at: call slow#hdr
```

A name missing from `.env.schema` is caught by `vc check`:

```console
$ vc check
error[V2106]: `${secret.API_TOKN}` is not declared in `.env.schema`
  --> services/slow/slow.api.yaml:39:16
   |
39 |       x-token: ${secret.API_TOKN}
   |                ^^^^^^^^^^^^^^^^^^ API_TOKN is not in .env.schema
   = help: add the line `API_TOKN=` to `.env.schema` at the project root, or fix the name
   = help: did you mean `API_TOKEN`?
   = fix: Replace with API_TOKEN (certain)
```

So is reading a secret through `${env.X}`, which would skip the masking:

```console
$ vc check
error[V2107]: `${env.API_TOKEN}` reads a secret that `.env.schema` declares
  --> services/slow/slow.api.yaml:39:16
   |
39 |       x-token: ${env.API_TOKEN}
   |                ^^^^^^^^^^^^^^^^ API_TOKEN is a secret
   = note: a declared secret is reachable only as `${secret.X}`, so it is masked everywhere
   = help: write `${secret.API_TOKEN}`
   = fix: Replace with secret.API_TOKEN (certain)
```

### varlock

`provider: varlock` loads values through [varlock](https://varlock.dev), which reaches 1Password, Vault, AWS and more. Without the tool installed:

```console
$ vc call slow#hdr
error: secrets: the varlock secrets provider is unavailable: `varlock` is not on PATH
```

With it on `PATH`, the values it returns are used:

```console
$ vc call slow#hdr
  "tokenStartsWith": "vl-t"
```

## How it behaves

- Values of four characters or more are replaced with `••••` in terminal output, reports and history.
- The `authorization`, `cookie` and `set-cookie` headers are always masked, secret or not.
- Add more masking with [`redact`](/vc-rs/reference/config/redact/).

<Aside type="caution">`vc init` does not add `.env` to `.gitignore`. Add it yourself before you put a value in it.</Aside>

## Common errors

- [V2106](/vc-rs/reference/diagnostics/v2106/): a secret not declared in `.env.schema`.
- [V2107](/vc-rs/reference/diagnostics/v2107/): a declared secret read with `${env.X}`.
- [V5111](/vc-rs/reference/diagnostics/v5111/): a secret with no value at run time.
