There are no proxy keys in `vibranium.config.yaml`: a proxy comes from the usual environment variables. HTTPS uses your system's certificate store, plus any roots in `http.tls.ca`, and `http.tls.clients` holds client certificates for mutual TLS (see [client certificates](/vc-rs/reference/auth/mtls/)).

```sh
export HTTPS_PROXY=http://proxy.corp.example:3128
export NO_PROXY=localhost,.internal.example
vc run
```

## Environment variables

| Variable | Notes |
| --- | --- |
| `HTTP_PROXY` | Proxy for `http://` requests. |
| `HTTPS_PROXY` | Proxy for `https://` requests, through a `CONNECT` tunnel. |
| `NO_PROXY` | Hosts that skip the proxy. |

Upper-case names are read first, then lower-case (`http_proxy`).

## Examples

In [the project these pages use](/vc-rs/reference/config/#the-project-these-pages-use), a proxy that is not running makes every call fail:

```console
$ HTTP_PROXY=http://127.0.0.1:9 vc call slow#wait
✗ cannot connect to 127.0.0.1:9: Connection refused (os error 61)
```

`NO_PROXY` lets local calls skip it:

```console
$ HTTP_PROXY=http://127.0.0.1:9 NO_PROXY=localhost vc call slow#wait
200 OK · 508 ms · api expect passed
{
  "sleptMs": 500
```

The lower-case name works too:

```console
$ http_proxy=http://127.0.0.1:9 vc call slow#wait
✗ cannot connect to 127.0.0.1:9: Connection refused (os error 61)
```

Adding a proxy key to the config is an error:

```yaml wrong V1004 title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  proxy: http://p:8080
```

```console
$ vc check
error[V1004]: unknown key `proxy` in configHttp
 --> vibranium.config.yaml:6:3
  |
6 |   proxy: http://p:8080
  |   ^^^^^ not a known key
  = help: expected one of `tls`, `retry`
```

## How it behaves

- Only `http://` proxy URLs are supported.
- Certificates are always verified. The trusted roots are your OS certificate store, so a company CA that your OS trusts works.
- `http.tls.ca` adds roots on top of the OS store: a path or inline PEM, or a list of them. There is no setting to skip verification.

<Aside>Not built yet: `vc check` checks `http.tls`, but a run does not load its roots or certificates until [#105](https://github.com/v007m/vc-rs/issues/105) lands in full. Until then, add a private CA to your OS certificate store.</Aside>
