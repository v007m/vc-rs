`.env.schema` lists the secret names a project uses, one `NAME=` line each, never the values. `vc init` creates it.

```ini title=".env.schema"
# The secret names this project uses, one NAME= line each, never their values.
API_TOKEN=
SHOP_CLIENT_SECRET=
```

## Syntax

| Line | Example | Notes |
| --- | --- | --- |
| `NAME=` | `API_TOKEN=` | Declares one secret. Leave the value empty. |
| `# @optional` | `# @optional` above `NAME=`, or `NAME= # @optional` | The secret may be unset (Varlock's convention). A run that reads it still needs a value at that point. |
| `# comment` | `# @sensitive` | Comments and other `# @...` annotations are allowed. |

The file's path is set by [`secrets.schema`](/vc-rs/reference/config/secrets/). The default is `.env.schema` at the project root.

## Examples

Reading a declared secret:

```yaml title="services/slow/slow.api.yaml"
  - id: hdr
    path: /hdr
    headers:
      x-token: ${secret.API_TOKEN}
```

```console
$ vc check
0 errors · 0 warnings · 9 files checked
```

A name the schema does not declare:

```console
$ vc check
error[V2106]: `${secret.OTHER}` is not declared in `.env.schema`
  --> services/slow/slow.api.yaml:38:16
   |
38 |       x-token: ${secret.OTHER}
   |                ^^^^^^^^^^^^^^^ OTHER is not in .env.schema
   = help: add the line `OTHER=` to `.env.schema` at the project root, or fix the name
```

A secret only some runs need, marked optional:

```ini title=".env.schema"
API_TOKEN=
# @optional  only the partner tests read it
PARTNER_KEY=
```

`vc run` with `PARTNER_KEY` unset runs every test. Only a test that reads `${secret.PARTNER_KEY}` fails, with V5114, and it sends nothing.

Reading a declared secret through `env` would skip the masking, so it is refused:

```console
$ vc check
error[V2107]: `${env.API_TOKEN}` reads a secret that `.env.schema` declares
  --> services/slow/slow.api.yaml:38:16
   |
38 |       x-token: ${env.API_TOKEN}
   |                ^^^^^^^^^^^^^^^^ API_TOKEN is a secret
   = note: a declared secret is reachable only as `${secret.X}`, so it is masked everywhere
   = help: write `${secret.API_TOKEN}`
   = fix: Replace with secret.API_TOKEN (certain)
```

`vc check --fix` offers that fix and asks before it writes.

## How it behaves

- `vc check` compares every `${secret.X}` and `${env.X}` with the schema.
- A declared secret is reachable only as `${secret.X}`.
- Values come from the [secrets provider](/vc-rs/reference/config/secrets/): the environment and `.env` by default.
- Before any request, `vc run`, `vc call` and `vc load` check the declared secrets that what they run reads: the selected tests, their apis, auth and lifecycle blocks, and the run-wide vars. One without a value (unset, or blank) stops them with V5114. A secret nothing selected reads may be unset.
- An `# @optional` secret is never checked before the run, and `vc check` never asks for its value. A test that reads one left unset fails with V5114 when it renders, before it sends; the other tests still run.
- Commit `.env.schema`. It holds no values.

## Common errors

- [V2106](/vc-rs/reference/diagnostics/v2106/): `${secret.X}` names a secret the schema does not declare.
- [V2107](/vc-rs/reference/diagnostics/v2107/): `${env.X}` reads a declared secret.
- [V5114](/vc-rs/reference/diagnostics/v5114/): a declared secret the run reads has no value.
