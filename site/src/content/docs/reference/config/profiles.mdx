A profile is a named set of values that replace the config's [`vars`](/vc-rs/reference/config/vars/). Use one per environment: `dev`, `staging`, `prod`.

```yaml title="vibranium.config.yaml"
profiles:
  - id: default
    default: true
  - id: staging
    vars:
      region: us
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `profiles` | list | — | yes | At least one profile. |
| `profiles[].id` | text | — | yes | A lower-case word: `staging`, `eu`. |
| `profiles[].default` | boolean | `false` | no | Active when no profile is named. Only one may be `true`. |
| `profiles[].name` | text | none | no | A display name. |
| `profiles[].vars` | map | none | no | Values that replace the config's `vars`. |
| `profiles[].agents` | map | none | no | What AI agents may do. See [agents](/vc-rs/reference/config/agents/). |

## Examples

Which profile is active, and why:

```console
$ vc config explain profile
profile = default  (vibranium.config.yaml)

$ VIB_PROFILE=staging vc config explain profile
profile = staging  (VIB_PROFILE)
  over default  (vibranium.config.yaml)
```

Several profiles apply in order. Later ones win:

```console
$ vc config explain vars.region --profile staging,eu
vars.region = dotenv  (.env)
  over eu  (profile eu)
  over us  (profile staging)
  over local  (vibranium.config.yaml)
```

Here `.env` still wins, because it sits above profiles in the [layers](/vc-rs/reference/config/layering/).

An unknown profile:

```console
$ vc run slow.timing --profile prod
error: --profile: no profile `prod`
  = help: the profiles are default, staging, eu
```

Two defaults:

```console
$ vc check
error[V3102]: profile `staging` is a second default profile
  --> vibranium.config.yaml:31:14
   |
29 |     default: true
   |              ---- `default` is the default
30 |   - id: staging
31 |     default: true
   |              ^^^^ also `default: true`
   = help: mark one profile `default: true`; pick another for a run with `--profile`
```

No profiles at all:

```console
$ vc check
error[V3101]: the config defines no profile
 --> vibranium.config.yaml:8:1
  |
8 | syntaxVersion: 2
  | ^^^^^^^^^^^^^ in this config
  = help: add `profiles:` with one profile marked `default: true`, such as `- id: dev`
```

A profile ID that is not lower case is a warning:

```console
$ vc check
warning[V4004]: profile `Eu` is not a lower-case word
  --> vibranium.config.yaml:33:9
   |
33 |   - id: Eu
   |         ^^ rename it
   = help: profiles are lower-case single words: `eu`, also where it is used
```

## How it behaves

- Name a profile with `--profile staging` or `VIB_PROFILE=staging`. Otherwise the one marked `default: true` applies.
- A profile changes values, never logic.
- A var a profile sets replaces the config's value whole. A map is not merged.
- Api and test files may have their own `profiles` list, to change that file's `vars`. Each ID there must exist in the config.

## Common errors

- [V3101](/vc-rs/reference/diagnostics/v3101/): no profiles, or none marked `default: true` while neither the user config, `.env` nor `VIB_PROFILE` names one. A run without `--profile` would have none active.
- [V3102](/vc-rs/reference/diagnostics/v3102/): a second default profile.
- [V4004](/vc-rs/reference/diagnostics/v4004/): a profile ID that is not a lower-case word.
