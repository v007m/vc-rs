`${fake.<module>.<name>}` makes a realistic value, such as a name, an email or a date, each time the template is rendered.

```yaml title="services/sample/basics.test.yaml"
tests:
  - id: createsUser
    name: Creates a user
    call: sample#createUser
    vars:
      name: ${fake.person.fullName}
      email: ${fake.internet.email}
```

## Syntax

| Part | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `fake.<module>.<name>` | template root | — | yes | One of the 25 names below. Any other name is [V2002](/vc-rs/reference/diagnostics/v2002/). |
| arguments | literals in `(…)` | per generator | no | Whole numbers, numbers, or text in **single quotes**: `fake.lorem.words(5)`, `fake.string.fromRegExp('[a-z]{4}')`. No templates, no `null`. |

| `fake.number.int(min, max)` | two whole numbers | `0`, `9007199254740991` | `(1, 100)` → `90` |
| `fake.number.float(min, max)` | two numbers | `0`, `1` | `(0, 1)` → `0.4326372421346605` |

| `fake.date.past` | none | — | `2026-01-03T04:41:45.695Z` |
| `fake.date.future` | none | — | `2026-12-29T11:31:33.829Z` |
| `fake.date.recent` | none | — | `2026-11-10T16:46:38.83Z` |
| `fake.helpers.arrayElement(a, b, …)` | one or more literals | required | `('PRIVATE', 'PUBLIC')` → `PUBLIC` |

`number.int`, `number.float` and `commerce.price` give numbers; the rest give text. `helpers.arrayElement` gives back whichever item it picked, so `arrayElement(1, 2, 3)` gives a number.

## Examples

### A user with a generated name and email

The simplest use: let the api's vars default to fake values, so every call makes a new user.

```yaml title="services/sample/sample.api.yaml"
  - id: createUser
    name: Create a user
    method: POST
    path: /users
    vars:
      name: ${fake.person.fullName}    # a new realistic value on every call
      email: ${fake.internet.email}
    body:
      name: ${var.name}
      email: ${var.email}
```

### Arguments

Counts and ranges go in parentheses. Text arguments use single quotes.

```yaml
body:
  label: user-${fake.string.alphanumeric(4)}      # user-dVxS
  bio: ${fake.lorem.words(8)}
  age: ${fake.number.int(18, 99)}
  price: ${fake.commerce.price(5, 50)}
  plan: ${fake.helpers.arrayElement('free', 'team', 'enterprise')}
```

### Every generator in one request

This test sends one of each to the demo's `/echo` endpoint, which returns the body it got. It is how the sample column above was made.

```yaml title="services/sample/gen.test.yaml"
tests:
  - id: generatesAll
    name: Generates one value of each kind
    call: sample#echo
    body:
      fullName: ${fake.person.fullName}
      uuid: ${fake.string.uuid}
      alnum: ${fake.string.alphanumeric(12)}
      regexp: ${fake.string.fromRegExp('[A-Z]{3}-[0-9]{4}')}
      words: ${fake.lorem.words(5)}
      int: ${fake.number.int(1, 100)}
      past: ${fake.date.past}
      pick: ${fake.helpers.arrayElement('PRIVATE', 'PUBLIC')}
```

Run it with `vc run sample.gen --seed 42`; the demo echoes the values back, and the same seed always gives the same values.

## How it behaves

- **Dates** are ISO 8601 text in UTC. `date.past` is within the year before the run started, `date.future` within the year after, and `date.recent` within the day before.
- **Emails** always use the reserved domains `example.com`, `example.org` or `example.net`, so a test never mails a real person.
- **Ranges** are inclusive: `number.int(1, 3)` can give 1, 2 or 3. The first number must not be larger than the second.
- **Arguments are literals.** You can't pass a template such as `${var.max}` into a generator. Use a [named generator](/vc-rs/reference/data/named-generators/) for a shape you reuse.
- **When a value is made** depends on where the template sits: a var made from a generator holds one value for the whole test instance, while a generator written straight into a body makes a new value at each spot. See [Generation and seeds](/vc-rs/reference/data/seeds/).
- **Faker modules are reserved.** `person`, `internet`, `phone`, `location`, `string`, `lorem`, `number`, `commerce`, `date` and `helpers` can't be used as names of your own generators ([V2006](/vc-rs/reference/diagnostics/v2006/)).

## Common errors

| Code | When | Real message |
| --- | --- | --- |
| [V2002](/vc-rs/reference/diagnostics/v2002/) | The generator name is unknown | `${fake.person.fullname}` lists all 25 names in a note |
| [V2302](/vc-rs/reference/diagnostics/v2302/) | Wrong arguments | `` `fake.lorem.words` takes nothing or one whole number from 0 to 10000 ``; `` `fake.number.int` takes nothing or two whole numbers, min then max ``; `` `fake.lorem.word` takes no arguments `` |
| [V2305](/vc-rs/reference/diagnostics/v2305/) | Bad argument syntax | `text arguments take single quotes` (with a certain fix: write `'x'`); `` `null` is not an argument `` |
| [V2309](/vc-rs/reference/diagnostics/v2309/) | `fromRegExp` pattern outside the supported subset | see [fromRegExp patterns](/vc-rs/reference/data/fromregexp/) |

```console

  = help: use single quotes
  = fix: Write '[a-z]{3}' (certain)

```
