`anyOf` passes when at least one matcher in the list passes.

```yaml
expect:
  body:
    match:
      body.qty: {anyOf: [{eq: 0}, {gt: 2}]}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `anyOf` | list of matchers | — | yes | At least one entry must pass. |

## Examples

The examples call `sample#echoOrder`, which posts a sample order to the demo service; the demo sends it back under `body`. See [Following along](/vc-rs/reference/matchers/#following-along).

### Zero or more than two



```yaml title="services/sample/anyof.test.yaml"
tests:
  - id: qtyRule
    name: Quantity is 0 or above 2
    call: sample#echoOrder
    expect:
      body:
        match:
          body.qty: {anyOf: [{eq: 0}, {gt: 2}]}
```

### Null or a date

Allow a field that is either empty or well formed.

```yaml title="services/sample/anyof.test.yaml"
tests:
  - id: noteOrDate
    name: Note is null or a date
    call: sample#echoOrder
    expect:
      body:
        match:
          body.note: {anyOf: [{eq: null}, {format: date}]}
```

## How it behaves

- At least one entry must pass.
- For a choice between plain values, [in](/vc-rs/reference/matchers/in/) is shorter.
- The argument must be a list of matchers.

## Common errors

- [V2306](/vc-rs/reference/diagnostics/v2306/): the argument is not a list of matchers.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
