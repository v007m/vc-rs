`format` passes when a string has one of six common formats.

```yaml
expect:
  body:
    match:
      body.email: {format: email}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `format` | `email`, `uuid`, `uri`, `date`, `dateTime` or `ipv4` | — | yes | Checks the shape of the text only. |

## Examples

The examples call `sample#echoOrder`, which posts a sample order to the demo service; the demo sends it back under `body`. See [Following along](/vc-rs/reference/matchers/#following-along).

### Email and UUID



```yaml title="services/sample/format.test.yaml"
tests:
  - id: emailAndUuid
    name: Email and UUID look right
    call: sample#echoOrder
    expect:
      body:
        match:
          body.email: {format: email}
          body.uuid: {format: uuid}
```

### Dates and times

## How it behaves

- `email`: some text, `@`, a domain with a dot. No spaces.
- `uuid`: 8-4-4-4-12 hex digits, any case.
- `uri`: a scheme, a colon, then text with no spaces, such as `https://shop.example/a`.
- `date`: `YYYY-MM-DD`. `dateTime`: RFC 3339, such as `2026-11-10T09:30:00Z`.
- `ipv4`: four numbers from 0 to 255, separated by dots.
- Only strings can pass. A missing value fails. For other shapes, use [regex](/vc-rs/reference/matchers/regex/).

## Common errors

- [V2306](/vc-rs/reference/diagnostics/v2306/): an unknown format, such as `phone`. The help line lists the six names.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
