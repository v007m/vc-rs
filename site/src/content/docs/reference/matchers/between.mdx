`between` passes when the value is at least the low bound and at most the high bound.

```yaml
expect:
  body:
    match:
      body.total: {between: [40, 50]}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `between` | list of two values: `[low, high]` | — | yes | Both ends are included. Values are numbers, strings, durations or sizes. |

## Examples

The examples call `sample#echoOrder`, which posts a sample order to the demo service; the demo sends it back under `body`. See [Following along](/vc-rs/reference/matchers/#following-along).

### A number range

The total is 42.5.

```yaml title="services/sample/between.test.yaml"
tests:
  - id: totalInRange
    name: Total is between 40 and 50
    call: sample#echoOrder
    expect:
      body:
        match:
          body.total: {between: [40, 50]}
```

## How it behaves

- The range is inclusive on both ends.
- The list must hold exactly two values, low first.
- Ordered comparisons work on two numbers or on two strings. Strings compare by character code, so ISO dates such as `2026-11-10` sort correctly. A number compared with a string fails. Under `timing` the argument is a duration such as `500ms`, and under `size` it is a size such as `1kb`.
- A missing value fails.

## Common errors

- [V2306](/vc-rs/reference/diagnostics/v2306/): the argument is not a list (`between needs a list of two values`) or does not hold exactly two values (`between needs exactly two values, low and high`).
- [V2301](/vc-rs/reference/diagnostics/v2301/): under `timing` or `size`, a bound has no unit.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
