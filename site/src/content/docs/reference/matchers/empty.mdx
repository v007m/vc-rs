`empty: true` passes for an empty string, list or object. `empty: false` passes when it has content.

```yaml
expect:
  body:
    match:
      body.tags: {empty: false}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `empty` | `true` or `false` | — | yes | Works on strings, lists and objects. |

## Examples

The examples call `sample#echoOrder`, which posts a sample order to the demo service; the demo sends it back under `body`. See [Following along](/vc-rs/reference/matchers/#following-along).

### A list with items



```yaml title="services/sample/empty.test.yaml"
tests:
  - id: hasTags
    name: Tags are set
    call: sample#echoOrder
    expect:
      body:
        match:
          body.tags: {empty: false}
```

### Missing values fail both ways

A path that is not there is neither empty nor non-empty.

```yaml title="services/sample/empty.test.yaml"
tests:
  - id: failsOnMissing
    name: Missing list has items
    call: sample#echoOrder
    expect:
      body:
        match:
          body.missing: {empty: false}
```

## How it behaves

- A string is empty when it has no characters; a list when it has no items; an object when it has no keys.
- A missing value, a number, a boolean or `null` fails both `empty: true` and `empty: false`.
- To check an exact size, use [length](/vc-rs/reference/matchers/length/).

## Common errors

- [V2306](/vc-rs/reference/diagnostics/v2306/): the argument is not `true` or `false`.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
