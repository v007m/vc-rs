`allOf` passes when every matcher in the list passes.

```yaml
expect:
  body:
    match:
      body.id: {allOf: [{startsWith: ord_}, {length: 7}]}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `allOf` | list of matchers | — | yes | Every entry must pass. |

## Examples

The examples call `sample#echoOrder`, which posts a sample order to the demo service; the demo sends it back under `body`. See [Following along](/vc-rs/reference/matchers/#following-along).

### Two rules on one value



```yaml title="services/sample/allof.test.yaml"
tests:
  - id: idShape
    name: ID starts with ord_ and has 7 characters
    call: sample#echoOrder
    expect:
      body:
        match:
          body.id: {allOf: [{startsWith: ord_}, {length: 7}]}
```

### The same thing in one map

Several matchers in one map must all pass too, so this is equivalent and shorter.

```yaml title="services/sample/allof.test.yaml"
tests:
  - id: idShapeMap
    name: ID is a 7-character string starting with ord_
    call: sample#echoOrder
    expect:
      body:
        match:
          body.id: {type: string, length: 7, startsWith: ord_}
```

## How it behaves

- Every entry must pass. An empty list passes.
- A map with several matchers, such as `{gte: 1, lte: 10}`, means the same as `allOf`. Use `allOf` when you repeat a matcher, such as two `regex` patterns, which one map cannot hold.
- The argument must be a list of matchers.

## Common errors

- [V2306](/vc-rs/reference/diagnostics/v2306/): the argument is not a list: `allOf needs a list of matchers`.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
