`headers` checks response headers. Each key is a header name and each value is a literal or a matcher.

```yaml
expect:
  headers:
    content-type: {contains: json}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `headers.<name>` | literal or matcher | — | no | Names are case-insensitive. Values are strings. |

## Examples

The examples call `sample#listUsers` on the demo service, which answers `[{"id":"1","name":"Ada Lovelace"},{"id":"2","name":"Grace Hopper"}]`. See [Following along](/vc-rs/reference/matchers/#following-along).

### Check the content type

Header names are case-insensitive, so `Content-Type` and `content-type` are the same check.

```yaml title="services/sample/headers.test.yaml"
tests:
  - id: answersJson
    name: Answers JSON
    call: sample#listUsers
    expect:
      headers:
        Content-Type: {contains: json}
```

### A failing literal

A literal header value must match exactly.

```yaml title="services/sample/headers.test.yaml"
  - id: failsOnHtml
    name: Answers HTML
    call: sample#listUsers
    expect:
      headers:
        content-type: text/html
```

### A missing header

Use `exists` to require a header, or `exists: false` to forbid one.

```yaml title="services/sample/headers.test.yaml"
tests:
  - id: failsOnRequestId
    name: Sends a request ID
    call: sample#listUsers
    expect:
      headers:
        x-request-id: {exists: true}
```

## How it behaves

- Header names are matched without regard to case.
- Header values are strings. Use `regex`, `contains` or `startsWith` for partial matches.
- Each header is its own check, keyed by its name, so a test can replace one header check from the api and keep the rest.

## Common errors

- [V1004](/vc-rs/reference/diagnostics/v1004/): a misspelled matcher next to a real one, such as `{gt: 1, gtt: 2}`. The help line suggests the closest name. A misspelled name on its own is not flagged: the map is compared as a literal value instead.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
