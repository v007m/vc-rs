`notIn` passes when the value equals none of the values in the list.

```yaml
expect:
  body:
    match:
      body.status: {notIn: [closed, cancelled]}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `notIn` | list | — | yes | Each element is compared deeply, like `eq`. |

## Examples

The examples call `sample#echoOrder`, which posts a sample order to the demo service; the demo sends it back under `body`. See [Following along](/vc-rs/reference/matchers/#following-along).

### Rule out several values



```yaml title="services/sample/notin.test.yaml"
tests:
  - id: isOpen
    name: Order is not closed or cancelled
    call: sample#echoOrder
    expect:
      body:
        match:
          body.status: {notIn: [closed, cancelled]}
```

### A missing path passes

Nothing is in the list, so a missing path passes. Add `exists: true` when the field is required.

```yaml title="services/sample/notin.test.yaml"
tests:
  - id: passesOnMissing
    name: Missing field is not closed
    call: sample#echoOrder
    expect:
      body:
        match:
          body.state: {notIn: [closed]}
```

```console
$ vc run sample.notin#passesOnMissing

```

## How it behaves

- The value must deeply equal no element of the list.
- A missing path passes. Pair it with `exists: true` when the field is required.
- The argument must be a list.

## Common errors

- [V2306](/vc-rs/reference/diagnostics/v2306/): the argument is not a list.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
