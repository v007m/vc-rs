`gte` passes when the value at the path is greater than or equal to the argument (`>=`).

```yaml
expect:
  body:
    match:
      body.total: {gte: 42.5}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `gte` | number, string, duration or size | — | yes | Under `timing` the argument is a duration (`500ms`); under `size` it is a size (`1kb`). |

## The API

The examples call `sample#echoOrder` and `sample#listUsers`. `echoOrder` posts a sample order to the demo's `/echo`, and the demo sends the request back, so the order shows up under `body`. `listUsers` sends `GET /users`, and the demo answers with two users. Here are the fields these examples check; [Following along](/vc-rs/reference/matchers/#following-along) has the whole entry and how to start the demo.

```yaml title="services/sample/sample.api.yaml (excerpt)"
  - id: listUsers
    name: List users
    method: GET
    path: /users
  ...
  - id: echoOrder
    name: Echo a sample order
    method: POST
    path: /echo
    body:
      total: 42.5
      day: "2026-11-10"
      ...
```

```console
$ vc call sample#echoOrder
200 OK · 3 ms · api expect passed
{
  "body": {
    "day": "2026-11-10",
    "total": 42.5,
    ...
  },
  ...
}
```

The order total is 42.5.

```yaml title="services/sample/gte.test.yaml"

  - id: totalGte425
    name: Total >= 42.5
    call: sample#echoOrder
    expect:
      body:
        match:
          body.total: {gte: 42.5}
```

### Use a var as the bound

The argument can be a template. A quoted template that renders a number is compared as a number.

```yaml title="services/sample/gte.test.yaml"
tests:
  - id: totalFromVar
    name: Total against a var
    call: sample#echoOrder
    vars:
      limit: 42.5
    expect:
      body:
        match:
          body.total: {gte: "${var.limit}"}
```

## How it behaves

- Ordered comparisons work on two numbers or on two strings. Strings compare by character code, so ISO dates such as `2026-11-10` sort correctly. A number compared with a string fails. Under `timing` the argument is a duration such as `500ms`, and under `size` it is a size such as `1kb`.
- A missing value fails. A value of a different type also fails, for example a string against a number.
- Combine bounds in one map, such as `{gte: 1, lt: 100}`, or use [between](/vc-rs/reference/matchers/between/) for an inclusive range.

## Common errors

- [V1004](/vc-rs/reference/diagnostics/v1004/): a misspelled matcher next to a real one, such as `{gt: 1, gtt: 2}`. The help line suggests the closest name.
- [V3208](/vc-rs/reference/diagnostics/v3208/): a warning for a misspelled matcher on its own when its name has five or more letters, such as `{startWith: A}`. It is still compared as a literal object; fix the name, or put the object under `eq:` to keep it.
- [V2301](/vc-rs/reference/diagnostics/v2301/): under `timing` or `size`, the bound has no unit, such as `500` instead of `500ms`.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
