`exists: true` passes when the path is in the body. `exists: false` passes when it is not.

```yaml
expect:
  body:
    match:
      body.id: {exists: true}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `exists` | `true` or `false` | — | yes | A field set to `null` counts as present. |

## Examples

The examples call `sample#echoOrder`, which posts a sample order to the demo service; the demo sends it back under `body`. See [Following along](/vc-rs/reference/matchers/#following-along).

### Require a field



```yaml title="services/sample/exists.test.yaml"
tests:
  - id: hasId
    name: Order has an ID
    call: sample#echoOrder
    expect:
      body:
        match:
          body.id: {exists: true}
```

A missing value is reported as `got nothing`.

## How it behaves

- Only presence counts. A key whose value is `null` exists.
- Most matchers fail on a missing path, so `exists: true` is often implied. Write it when you want a clear failure message.
- `ne`, `notIn` and `not` pass on a missing path. Add `exists: true` next to them when the field is required.

## Common errors

- [V2306](/vc-rs/reference/diagnostics/v2306/): the argument is not `true` or `false`: `exists takes true or false`.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
