`ne` passes when the value at the path is not equal to the argument.

```yaml
expect:
  body:
    match:
      body.status: {ne: closed}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `ne` | any value | — | yes | Compared deeply, like `eq`. |

## Examples

The examples call `sample#echoOrder`, which posts a sample order to the demo service; the demo sends it back under `body`. See [Following along](/vc-rs/reference/matchers/#following-along).

### Rule out a value

Check that an order is not closed.

```yaml title="services/sample/ne.test.yaml"
tests:
  - id: isNotClosed
    name: Order is not closed
    call: sample#echoOrder
    expect:
      body:
        match:
          body.status: {ne: closed}
```


### Require a value that is not null

`ne: null` passes for any value other than null.

```yaml title="services/sample/ne.test.yaml"
tests:
  - id: hasEmail
    name: Email is set
    call: sample#echoOrder
    expect:
      body:
        match:
          body.email: {ne: null}
```

`note` is null, so `ne: null` fails.

### A missing path passes

A path that is not in the body is not equal to anything, so `ne` passes. Add `exists: true` when the field must be there.

```yaml title="services/sample/ne.test.yaml"
tests:
  - id: passesOnMissing
    name: Missing field is not closed
    call: sample#echoOrder
    expect:
      body:
        match:
          body.state: {ne: closed}
  - id: needsTheField
    name: State is present and not closed
    call: sample#echoOrder
    expect:
      body:
        match:
          body.state: {exists: true, ne: closed}
```

```console
$ vc run sample.ne#passesOnMissing sample.ne#needsTheField
plan  2 tests in 1 file · profile default

✓ sample.ne#passesOnMissing                                       6ms
✕ sample.ne#needsTheField                                         1ms
  error[V5101]: expect.body.match.body.state
    --> services/sample/ne.test.yaml:36:23

     |                       ^^^^^^^^^^^^^^^^^^^^^^^^^^ expected {"exists":true,"ne":"closed"}, got nothing

1 passed · 1 failed                                          9ms · profile default
```

## How it behaves

- `ne` is the opposite of [eq](/vc-rs/reference/matchers/eq/): deep comparison, numbers by value.
- A missing path passes `ne`. Pair it with `exists: true` when the field is required.
- To rule out several values, use [notIn](/vc-rs/reference/matchers/not-in/).

## Common errors

- [V1004](/vc-rs/reference/diagnostics/v1004/): a misspelled matcher next to a real one, such as `{gt: 1, gtt: 2}`. The help line suggests the closest name.
- [V3208](/vc-rs/reference/diagnostics/v3208/): a warning for a misspelled matcher on its own when its name has five or more letters, such as `{startWith: A}`. It is still compared as a literal object; fix the name, or put the object under `eq:` to keep it.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
