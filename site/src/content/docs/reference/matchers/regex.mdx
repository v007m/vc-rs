`regex` passes when a string matches the pattern anywhere in it.

```yaml
expect:
  body:
    match:
      body.id: {regex: "^ord_\\d+$"}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `regex` | string | — | yes | Rust regex syntax. Not anchored: add `^` and `$` to match the whole string. |

## Examples

The examples call `sample#echoOrder`, which posts a sample order to the demo service; the demo sends it back under `body`. See [Following along](/vc-rs/reference/matchers/#following-along).

### Match the whole string

Quote the pattern, and double each backslash inside double quotes.

```yaml title="services/sample/regex.test.yaml"
tests:
  - id: idPattern
    name: ID is ord_ and digits
    call: sample#echoOrder
    expect:
      body:
        match:
          body.id: {regex: "^ord_\\d+$"}
```


### Ignore case

Start the pattern with `(?i)`.

```yaml title="services/sample/regex.test.yaml"
tests:
  - id: idAnyCase
    name: ID starts with ORD in any case
    call: sample#echoOrder
    expect:
      body:
        match:
          body.id: {regex: "(?i)^ORD"}
```

```console
$ vc run sample.regex#idAnyCase
```


### Numbers do not match

`regex` reads strings only. To check a number, use a comparison.

```yaml title="services/sample/regex.test.yaml"
tests:
  - id: failsOnNumber
    name: Quantity has a 3
    call: sample#echoOrder
    expect:
      body:
        match:
          body.qty: {regex: "3"}
```

## How it behaves

- The pattern uses [Rust regex syntax](https://docs.rs/regex/latest/regex/#syntax). It has no look-around or back-references.
- The match is unanchored: `ord` matches `my_ord_1`. Use `^` and `$` for a full match.
- `vc check` compiles every pattern and reports one that does not compile.
- Only strings can pass. A number or a missing value fails.

## Common errors

- [V2306](/vc-rs/reference/diagnostics/v2306/): the pattern does not compile, for example `regex has an invalid pattern: ... unclosed character class`.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
