`timing` checks how long a request took, phase by phase. Write durations with a unit.

```yaml
expect:
  timing:
    total: {lt: 500ms}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `timing.dns` | matcher with durations | — | no | DNS lookup. |
| `timing.connect` | matcher with durations | — | no | TCP connect. |
| `timing.tls` | matcher with durations | — | no | TLS handshake. |
| `timing.firstByte` | matcher with durations | — | no | Time to the first response byte. |
| `timing.download` | matcher with durations | — | no | Reading the body. |
| `timing.total` | matcher with durations | — | no | The whole request. |

## Examples

The examples call `sample#listUsers` on the demo service, which answers `[{"id":"1","name":"Ada Lovelace"},{"id":"2","name":"Grace Hopper"}]`. See [Following along](/vc-rs/reference/matchers/#following-along).

### Bound the total time



```yaml title="services/sample/timing.test.yaml"
tests:
  - id: answersQuickly
    name: Answers within 500 ms
    call: sample#listUsers
    expect:
      timing:
        total: {lt: 500ms}
```

```console
$ vc run sample.timing#answersQuickly
plan  1 test in 1 file · profile default

✓ sample.timing#answersQuickly                                    2ms

1 passed                                                     3ms · profile default
```

### Several phases




### A failing check


### A duration needs a unit

`vc check` rejects a bare number and offers a fix.

```yaml wrong title="services/sample/timingerrors.test.yaml"
tests:
  - id: noUnit
    name: No unit
    call: sample#listUsers
    expect:
      timing:
        total: {lt: 500}
```

```console
$ vc check
error[V2301]: invalid duration `500`
 --> services/sample/timingerrors.test.yaml:7:21
  |
7 |         total: {lt: 500}
  |                     ^^^
  = help: write a whole number and a unit: `250ms`, `2s`, `1m` or `12h`
  = fix: Write 500ms (certain)

1 error · 0 warnings · 41 files checked
```

### An unknown phase




## How it behaves

- Durations are a whole number and a unit: `250ms`, `2s`, `1m`, `12h`.
- The failure message shows durations in milliseconds.
- Timing checks depend on the network and the machine. Keep bounds generous in functional tests; use load tests for latency targets.

## Common errors

- [V2301](/vc-rs/reference/diagnostics/v2301/): the duration has no unit.
- [V1004](/vc-rs/reference/diagnostics/v1004/): the phase is not one of `dns`, `connect`, `tls`, `firstByte`, `download`, `total`.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
