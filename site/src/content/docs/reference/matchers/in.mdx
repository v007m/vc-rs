`in` passes when the value equals one of the values in the list.

```yaml
expect:
  body:
    match:
      body.status: {in: [active, pending]}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `in` | list | — | yes | Each element is compared deeply, like `eq`. |

## Examples

The examples call `sample#echoOrder`, which posts a sample order to the demo service; the demo sends it back under `body`. See [Following along](/vc-rs/reference/matchers/#following-along).

### One of several strings

Accept any of the statuses a new order can have.

```yaml title="services/sample/in.test.yaml"
tests:
  - id: hasOpenStatus
    name: Status is open
    call: sample#echoOrder
    expect:
      body:
        match:
          body.status: {in: [active, pending]}
```

### Status codes

`status` takes a matcher too. A plain list of codes does the same; see [status](/vc-rs/reference/matchers/status/).

```yaml title="services/sample/in.test.yaml"
tests:

    name: Answers 200 or 201
    call: sample#listUsers

      status: {in: [200, 201]}
```

## How it behaves

- The value must deeply equal one element of the list.
- A missing value fails.
- The argument must be a list.

## Common errors

- [V2306](/vc-rs/reference/diagnostics/v2306/): the argument is not a list: `in needs a list of values`.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
