`in` passes when the value equals one of the values in the list.

```yaml
expect:
  body:
    match:
      body.status: {in: [active, pending]}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `in` | list | — | yes | Each element is compared deeply, like `eq`. |

## The API

The examples call `sample#echoOrder` and `sample#listUsers`. `echoOrder` posts a sample order to the demo's `/echo`, and the demo sends the request back, so the order shows up under `body`. `listUsers` sends `GET /users`, and the demo answers with two users. Here are the fields these examples check; [Following along](/vc-rs/reference/matchers/#following-along) has the whole entry and how to start the demo.

```yaml title="services/sample/sample.api.yaml (excerpt)"
  - id: listUsers
    name: List users
    method: GET
    path: /users
  ...
  - id: echoOrder
    name: Echo a sample order
    method: POST
    path: /echo
    body:
      status: active
      qty: 3
      ...
```

```console
$ vc call sample#echoOrder
200 OK · 9 ms · api expect passed
{
  "body": {
    "qty": 3,
    "status": "active",
    ...
  },
  ...
}
```

## Examples

### One of several strings

Accept any of the statuses a new order can have.

```yaml title="services/sample/in.test.yaml"
tests:
  - id: hasOpenStatus
    name: Status is open
    call: sample#echoOrder
    expect:
      body:
        match:
          body.status: {in: [active, pending]}
```

```console
$ vc run sample.in#hasOpenStatus

```

## How it behaves

- The value must deeply equal one element of the list.
- A missing value fails.
- The argument must be a list.

## Common errors

- [V2306](/vc-rs/reference/diagnostics/v2306/): the argument is not a list: `in needs a list of values`.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
