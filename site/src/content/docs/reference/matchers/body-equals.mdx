`body.equals` passes when the whole body deeply equals the value.

```yaml
expect:
  body:
    equals:
      - {id: "1", name: Ada Lovelace}
      - {id: "2", name: Grace Hopper}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `body.equals` | any value | — | no | The whole body, compared deeply. |

## Examples

The examples call `sample#listUsers` on the demo service, which answers `[{"id":"1","name":"Ada Lovelace"},{"id":"2","name":"Grace Hopper"}]`. See [Following along](/vc-rs/reference/matchers/#following-along).

### Match the whole body

Quote `"1"`: the demo returns IDs as strings.

```yaml title="services/sample/bodyequals.test.yaml"
tests:
  - id: listsBothUsers
    name: Lists exactly two users
    call: sample#listUsers
    expect:
      body:
        equals:
          - {id: "1", name: Ada Lovelace}
          - {id: "2", name: Grace Hopper}
```

## How it behaves

- The body must equal the value exactly: no extra keys, no missing keys, and lists in the same order.
- The value is a literal. Matchers are not read inside it. To check a few fields and ignore the rest, use `body.match`.
- Large bodies make brittle tests. Prefer [body.schema](/vc-rs/reference/matchers/body-schema/) for shape and `body.match` for the values you care about.

## Common errors

- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
