`every` passes when each element of a list matches the nested matcher.

```yaml
expect:
  body:
    match:
      body.items[*].price: {every: {gt: 0}}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `every` | matcher or value | — | yes | A plain value means each element equals it. |

## The API

The examples call `sample#echoOrder`. It posts a sample order to the demo's `/echo`, and the demo sends the request back, so the order shows up under `body`. Here are the fields these examples check; [Following along](/vc-rs/reference/matchers/#following-along) has the whole entry and how to start the demo.

```yaml title="services/sample/sample.api.yaml (excerpt)"
  - id: echoOrder
    name: Echo a sample order
    method: POST
    path: /echo
    body:
      tags: [new, vip]
      items:
        - {sku: A1, price: 10}
        - {sku: B2, price: 32.5}
      empty: []
      ...
```


## Examples

### Every price is positive

A `[*]` path, such as `body.items[*].price`, collects one field from every element into a list. Use it to apply a matcher to one field of each element.

```yaml title="services/sample/every.test.yaml"
tests:
  - id: pricesPositive
    name: Every price is positive
    call: sample#echoOrder
    expect:
      body:
        match:
          body.items[*].price: {every: {gt: 0}}
```

### Use a list path for fields

Inside `every`, the matcher applies to the element itself. A map whose keys are not matcher names is a literal object, so this compares each item to the object `{price: {gt: 0}}`.

```yaml title="services/sample/every.test.yaml"
tests:
  - id: failsOnFieldMap
    name: Every item has a positive price
    call: sample#echoOrder
    expect:
      body:
        match:
          body.items: {every: {price: {gt: 0}}}
```

```console
$ vc run sample.every#failsOnFieldMap
plan  1 test in 1 file · profile default

✕ sample.every#failsOnFieldMap — Every item has a positive price    5ms

    --> services/sample/every.test.yaml:36:23
```

## How it behaves

- The value must be a list. Anything else, including a missing value, fails.
- An empty list passes.
- To check fields of each element, put the field in the path with `[*]`.

## Common errors

- [V1004](/vc-rs/reference/diagnostics/v1004/): a misspelled matcher next to a real one, such as `{gt: 1, gtt: 2}`. The help line suggests the closest name.
- [V3208](/vc-rs/reference/diagnostics/v3208/): a warning for a misspelled matcher on its own when its name has five or more letters, such as `{startWith: A}`. It is still compared as a literal object; fix the name, or put the object under `eq:` to keep it.
- [V2306](/vc-rs/reference/diagnostics/v2306/): a scalar matcher written straight on a `[*]` path, such as `body.items[*].price: {gt: 0}`. It would compare the whole list, so `vc check` refuses it. Wrap it in `every`, `some` or `none`.
- [V5101](/vc-rs/reference/diagnostics/v5101/): the check did not hold for the response. The report shows the expected and the actual value.
