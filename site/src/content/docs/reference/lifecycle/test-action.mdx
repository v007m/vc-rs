`test: <test ID>` runs another test's calls in order, as if you had written them in place. Use it when a multi-step setup already exists as a test.

```yaml title="services/lab/reuse.test.yaml"
tests:
  - id: makesAnItem
    standalone: false        # only for reuse; never runs on its own
    call: lab#createItem
    vars:
      label: reused

  - id: reusesWithProvides
    before:
      - test: lab.reuse#makesAnItem
        provides: [itemId]
    call: lab#whoami
    query:
      item: ${var.itemId}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `test` | test ID | — | yes | `<fileId>#<testId>` |
| `id` | camelCase text | — | in `beforeRun`/`beforeAll` | Shared saves live under it |
| `provides` | list of names | — | no | The names it saves; see [provides](/vc-rs/reference/lifecycle/provides/) |
| `timeout` | duration | — | no | Limit on all the reused test's calls together |
| `vars`, `auth`, `headers`, `query`, `body`, `expect`, `save`, `poll`, `retry`, `keep`, `cache` | | | no | Same meaning as on a `call` action |
| `repeat`, `forEach`, `parallel` | | | no | See [Loops on actions](/vc-rs/reference/lifecycle/loops/) |

On the reused test, `standalone: false` keeps it out of runs and reports.

## Examples

A reuse-only test. `vc run lab.reuse` runs only `reusesWithProvides`; selecting the reuse-only test itself runs nothing (exit 2):

```console
$ vc run lab.reuse
plan  1 test in 1 file · profile default

✓ lab.reuse#reusesWithProvides                                   15ms
```

The reused calls registered their cleanup as usual. The server saw:

```console
POST /items body={"label":"reused"}
GET /whoami?item=i8
DELETE /items/i8
```

Reuse a multi-step flow with a time budget for all of its calls:

```yaml
tests:
  - id: makesThreeItems
    standalone: false
    steps:
      - call: lab#createItem
        repeat: 3
        vars:
          label: item-${iteration.index}-of-${iteration.count}

  - id: reusesTheFlow
    before:
      - test: lab.loops#makesThreeItems
        timeout: 5s
        provides: [itemId]
    call: lab#whoami
    query:
      last: ${var.itemId}
```

Without `provides`, reading a value the reused test saved still works, with a warning:

```console
! V5108: `var.itemId` was saved by a `test:` step that does not declare it; add `provides: [itemId]` to that step
```

<Aside type="caution">
The reused test's own test-level `expect` is checked today. If it does not hold, the test that reuses it is blocked with a V5101 that points into the reused test.
</Aside>

## How it behaves

- Saved values arrive as if the calls were written in place: plain names in per-test blocks, under the action's `id` in `beforeRun` and `beforeAll`.
- Each reused call keeps its api's checks, and its api's cleanups are registered as usual.
- A cycle (a test that reuses itself, directly or through others) is a `vc check` error that prints the whole cycle:

```console
error[V2205]: `test:` reuse forms a cycle: lab.cyc#one → lab.cyc#two → lab.cyc#one
 --> services/lab/cyc.test.yaml:8:15
  |
8 |       - test: lab.cyc#one
  |               ^^^^^^^^^^^ this reuse closes the cycle
  = help: a test cannot reuse itself, directly or through other tests; move the shared steps into one test
```

- Past its `timeout`, the call in flight fails and the test that reuses it is blocked:

```console
⊘ lab.slowreuse#budgetsTheFlow blocked                           1.0s
  error[V5104]: the reused test ran past its `timeout`
     = at: test lab.slowreuse#slowFlow
```

## Common errors

- [V2003](/vc-rs/reference/diagnostics/v2003/): the test ID does not exist (`unknown test "lab.cyc#nope"`, with close names).
- [V2205](/vc-rs/reference/diagnostics/v2205/): the reuse forms a cycle.
- [V5108](/vc-rs/reference/diagnostics/v5108/): a value the reused test saved is read without `provides`.
- [V5109](/vc-rs/reference/diagnostics/v5109/): a name in `provides` was not saved.
- [V5104](/vc-rs/reference/diagnostics/v5104/): the calls ran past `timeout`.
