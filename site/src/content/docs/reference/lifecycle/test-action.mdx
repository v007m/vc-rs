`test: <test ID>` runs another test's calls in order, as if you had written them in place. Use it when a multi-step setup already exists as a test.

The example calls the demo server (`vc demo start`) through a small api file, `demo`. `demo#createItem` is a `POST /users` that answers 201 and saves the new user's ID as `itemId`; `demo#whoami` is a `GET /echo`, which sends the request back:

```yaml title="services/demo/demo.api.yaml (excerpt)"
baseUrl: ${var.sampleUrl}
apis:
  - id: createItem
    method: POST
    path: /users
    vars:
      label: item
      email: demo@example.com
    body:
      name: ${var.label}
      email: ${var.email}
    expect:
      status: 201
    save:
      itemId: ${response.body.id}
    cleanup:
      call: deleteItem
      vars:
        itemId: ${response.body.id}
  - id: deleteItem
    method: DELETE
    path: /users/${var.itemId}
  - id: whoami
    path: /echo
```

```yaml title="services/demo/reuse.test.yaml"
tests:
  - id: makesAnItem
    standalone: false        # only for reuse; never runs on its own
    call: demo#createItem
    vars:
      label: reused

  - id: reusesWithProvides
    before:
      - test: demo.reuse#makesAnItem
        provides: [itemId]
    call: demo#whoami
    query:
      item: ${var.itemId}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `test` | test ID | — | yes | `<fileId>#<testId>` |
| `id` | camelCase text | — | in `beforeRun`/`beforeAll` | Shared saves live under it |
| `provides` | list of names | — | no | The names it saves; see [provides](/vc-rs/reference/lifecycle/provides/) |
| `timeout` | duration | — | no | Limit on all the reused test's calls together |
| `vars`, `auth`, `headers`, `query`, `body`, `expect`, `save`, `poll`, `retry`, `keep`, `cache` | | | no | Same meaning as on a `call` action |
| `repeat`, `forEach`, `parallel` | | | no | See [Loops on actions](/vc-rs/reference/lifecycle/loops/) |

On the reused test, `standalone: false` keeps it out of runs and reports.

## Examples

A reuse-only test. `vc run demo.reuse` runs only `reusesWithProvides`; selecting the reuse-only test itself runs nothing (exit 2):

```console
$ vc run demo.reuse
plan  1 test in 1 file · profile default

✓ demo.reuse#reusesWithProvides                                  15ms
```

The reused calls registered their cleanup as usual. The server saw:

```console
POST /users body={"email":"demo@example.com","name":"reused"}
GET /echo?item=7
DELETE /users/7
```

Reuse a multi-step flow with a time budget for all of its calls:

```yaml
tests:
  - id: makesThreeItems
    standalone: false
    steps:
      - call: demo#createItem
        repeat: 3
        vars:
          label: item-${iteration.index}-of-${iteration.count}

  - id: reusesTheFlow
    before:
      - test: demo.loops#makesThreeItems
        timeout: 5s
    call: demo#whoami
    query:
      last: ${var.itemId}
```

`vc check` sees that the reused test saves `itemId` (through `demo#createItem`), so reading it needs no `provides`. Only a name the reused test saves from a `function:` step needs one; read without it, it is a warning:

```console
! V5108: `var.sessionId` was saved by a `test:` step that does not declare it; add `provides: [sessionId]` to that step
```

The reused test's own test-level `expect` is checked, as when it runs on its own. If it does not hold, the test that reuses it is blocked with a V5101 that points into the reused test.

## How it behaves

- Saved values arrive as if the calls were written in place: plain names in per-test blocks, under the action's `id` in `beforeRun` and `beforeAll`.
- Each reused call keeps its api's checks, and its api's cleanups are registered as usual.
- A cycle (a test that reuses itself, directly or through others) is a `vc check` error that prints the whole cycle:

```console
error[V2205]: `test:` reuse forms a cycle: demo.cyc#one → demo.cyc#two → demo.cyc#one
 --> services/demo/cyc.test.yaml:8:15
  |
8 |       - test: demo.cyc#one
  |               ^^^^^^^^^^^^ this reuse closes the cycle
  = help: a test cannot reuse itself, directly or through other tests; move the shared steps into one test
```

- Past its `timeout`, the call in flight fails and the test that reuses it is blocked:

```console
⊘ demo.slowreuse#budgetsTheFlow blocked                          1.0s
  error[V5104]: the reused test ran past its `timeout`
     = at: test demo.slowreuse#slowFlow
```

## Common errors

- [V2003](/vc-rs/reference/diagnostics/v2003/): the test ID does not exist (`unknown test "demo.cyc#nope"`, with close names).
- [V2205](/vc-rs/reference/diagnostics/v2205/): the reuse forms a cycle.
- [V5108](/vc-rs/reference/diagnostics/v5108/): a value the reused test saved from a `function:` step is read without `provides`.
- [V5109](/vc-rs/reference/diagnostics/v5109/): a name in `provides` was not saved.
- [V5104](/vc-rs/reference/diagnostics/v5104/): the calls ran past `timeout`.
