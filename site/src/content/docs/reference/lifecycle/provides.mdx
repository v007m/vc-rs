`vc check` cannot always see what a `function:` or `test:` action saves. `provides: [name, …]` declares those names, so a var read later counts as set.

```yaml
before:
  - function: ../../hooks/seed.ts#seedTenant
    vars:
      name: acme
    provides: [tenantId, profiles]
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `provides` | list of names | — | no | On `function:` and `test:` actions only |

## Examples

Without `provides`, `vc check` reports the var as never set:

```yaml
before:
  - function: ../../hooks/seed.ts#seedTenant
    vars:
      name: acme
call: lab#whoami
query:
  tenant: ${var.tenantId}
  profiles: ${var.profiles}
```

```console
error[V2101]: ${var.profiles} is used but never set
```

The check reports that no level sets `profiles` for the active profile. Add the names to `provides` and the check passes.

A reused test needs `provides` only for a name `vc check` can't see it save, one that a `function:` step inside it returns. What its calls save is already known. If `makesAnItem` also ran a function that returned `sessionId`:

```yaml
before:
  - test: lab.reuse#makesAnItem
    provides: [sessionId]
```

Using a name that an action saved without declaring it is a warning. The run goes on:

```console
! V5108: `var.profiles` was saved by a `function:` step that does not declare it; add `provides: [profiles]` to that step
```

Declaring a name the action did not save fails the action. This function returns `42`, so nothing is saved:

```yaml
before:
  - function: ../../hooks/seed.ts#returnsNothing
    provides: [tenantId]
```

```console
⊘ lab.fails#missesAProvidedName blocked                         238ms
  error[V5109]: declared in `provides` but not saved: `tenantId`
     = at: function hooks/seed.ts#returnsNothing
```

## How it behaves

- `provides` only tells `vc check` and the run what to expect. The values themselves come from what the action returns or saves.
- In `beforeRun` and `beforeAll`, the provided names live under the action's `id`, as with any shared save.
- `call:` actions do not need `provides`: vc reads the api's `save`.

## Common errors

- [V2101](/vc-rs/reference/diagnostics/v2101/): a var is used but never set. Add it to `provides`.
- [V5108](/vc-rs/reference/diagnostics/v5108/): a saved name is read but not declared (warning).
- [V5109](/vc-rs/reference/diagnostics/v5109/): a declared name was not saved.
