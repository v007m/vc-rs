`vc init` writes a sample service whose tests call `http://localhost:7421`. `vc demo start` runs a small service there, so the sample passes before you point Vibranium at your own API.

```console
$ vc demo start [--port <PORT>] [--detach]
$ vc demo stop [--port <PORT>]
```

## Options

| Flag | Value | Default | Description |
| --- | --- | --- | --- |
| `--port` | `<PORT>` | `7421` | The port to listen on, or for `stop`, the port it listens on |
| `--detach` | | | `start` only. Runs it in the background and returns once it answers; `vc demo stop` ends it |
| `--project` | `<DIR>` | | See [global flags](/vc-rs/reference/cli/#global-flags). The demo does not read the project |

## Examples

### Start it in the background

```console
$ vc demo start --detach
demo running on http://localhost:7421 (pid 71526); `vc demo stop` stops it
$ vc run
```

Without `--detach`, it stays in the foreground, says where it listens once it answers, and runs until you press Ctrl-C:

```console
$ vc demo start
demo running on http://localhost:7421 (pid 71530); Ctrl-C stops it
```

### Share a running demo

If the demo already answers on the port, `start` does not start a second one. It joins the running one instead, and the `stop` that follows leaves it running for whoever else uses it:

```console
$ vc demo start --detach
demo running on http://localhost:7421 (pid 71526); `vc demo stop` stops it
$ vc run
$ vc demo stop
stopped the demo on port 7421
```

Here `vc run` runs the sample, whose `beforeAll` calls `vc demo start` and finds your demo, and whose `afterAll` calls `vc demo stop`, which leaves your demo running. Two projects running the sample at once share one demo the same way: it stops when the last of them is done. A join counts while the process that ran `start` lives, and for an hour after it joined, since a `start` in a longer shell line outlives its shell. A run that crashed before its `stop` stops counting once both have passed.

```console
$ vc demo start --detach
a demo already answers on port 7421
$ vc demo stop
left the demo on port 7421 running, as another `vc demo start` uses it
```

`start` knows the demo by its `/echo`: a `200` that returns the path it was asked for and names the demo's pid in the `x-vc-demo-pid` header. If another program holds the port, even an echo server that answers the same path, `start` refuses rather than let your tests call that program:

```console
$ vc demo start --port 7454 --detach
error: port 7454 is taken by a program that is not the demo
  = help: pick another `--port`, and change `sampleUrl` in vibranium.config.yaml to match
```

### What it serves

| Request | Answer |
| --- | --- |
| `GET /users?limit=N` | `200` with Ada Lovelace (`1`), Grace Hopper (`2`) and the users created since, in ID order: `[{"id":"1","name":"Ada Lovelace"},{"id":"2","name":"Grace Hopper"}]` at first; the first N with `limit` |
| `GET /users/{id}` | `200` with the user, else `404` |
| `POST /users` | `201` with what was sent and a new `id` (`3`, then `4`, …, never one handed out before); `name` is `someone` when not sent. `400` with a JSON `error` without an `email`, with a `name` that is not text or a `role` other than `admin` or `member` |
| `PUT /users/{id}` | `200` with the user replaced by the body, checked as for `POST`; `404` for no such user |
| `PATCH /users/{id}` | `200` with the body's keys merged in (`null` removes a key), checked as for `POST`; `404` for no such user |
| `DELETE /users/{id}` | `204`; `404` for no such user |
| `POST /auth/token` | `200` `{"access_token":"demo-token-1","token_type":"Bearer","expires_in":3600}`, whatever the body, with the next number each time |
| `POST /oauth/token` | The same for the client `vc-client` with the secret `vc-secret` in HTTP Basic and `grant_type=client_credentials`; else `401` `invalid_client`, or `400` `invalid_request` or `unsupported_grant_type` |
| `GET /auth/me` | `200` `{"user":"demo"}` with `authorization: Bearer <token>` for a token from either; else `401` |
| `POST /auth/logout` | `204` with `authorization: Bearer <token>` for a valid token, which is then revoked, so a [`refreshOn`](/vc-rs/reference/auth/token-cache-refresh/) flow has to sign in again; else `401` as for `/auth/me` |
| `GET /openapi/users.yaml` | The users API as the demo serves it, in OpenAPI 3.0.3, with the server it was asked on; `users-v1.yaml` and `users-v2.yaml` are two older versions, for trying [`vc sync`](/vc-rs/reference/cli/sync/) |
| any `/echo` | `200` with the method, path, query, headers and body it received, and the demo's pid in the `x-vc-demo-pid` header |
| `GET /slow?ms=N` | `200` `{"sleptMs":N}` after N milliseconds (0 when `ms` is not given; `ms=` with no value is refused); N is at most `10000` |
| `GET /flaky?key=K&failTimes=N` | `{"attempt":n}`, counted per key: `503` for the first N attempts, then `200` |
| `GET /poll/{id}?after=N` | `200` `{"attempt":n,"status":"pending"}`, counted per ID, until attempt N, which and later ones are `"done"` |
| `GET /events?count=N` | `200` `text/event-stream`: N events (3 when not given, at most `100`), each `id: i` and `data: i`, then the end; after the number in a `last-event-id` header when one is sent. `drop=true` drops the connection after the last event, `dropAt=k` drops a first connection (one without `last-event-id`) after event k, `retry=ms` sends a `retry` first (at most `60000`) and `heartbeat=true` a comment before each event |
| `GET /ws` | A WebSocket (`101`; `426` without the upgrade): `{"type":"join"}` gets `{"type":"joined","memberId":"m1"}`, `{"type":"say","text":t}` gets `{"type":"message","text":t}` then `{"type":"seen"}`, the text `bye` a close `1000` `bye`, and any other message comes back as sent. A message is at most 64 KiB, and after `100` replies it closes with `1008`. The playground does not serve it |
| any `/status/{code}` | that status, with `{"status":code}`, for any code from `200` to `599`; no body for `204`, `205` and `304` |
| anything else | `404` |

It keeps users in memory until it stops. Ada and Grace cannot be changed or deleted (`403`). It holds at most 1024 created users, and a user is at most 4096 bytes without its `id`; past either it refuses with `400` and an `error` naming the limit. A token is valid until it is logged out or 1024 newer ones are handed out. The demo logs no tokens.

```console
$ curl -s -w ' %{http_code}\n' -X POST localhost:7421/users -d '{"name":"Alan Turing","email":"alan@example.com"}'
{"email":"alan@example.com","id":"3","name":"Alan Turing"} 201
$ curl -s -w ' %{http_code}\n' -X PATCH localhost:7421/users/3 -d '{"role":"admin"}'
{"email":"alan@example.com","id":"3","name":"Alan Turing","role":"admin"} 200
$ curl -s -w ' %{http_code}\n' -X PUT localhost:7421/users/1 -d '{"email":"a@example.com"}'
{"error":"users 1 and 2 are the demo's own; create a user to change"} 403
$ curl -s -w ' %{http_code}\n' -u vc-client:vc-secret -d grant_type=client_credentials localhost:7421/oauth/token
{"access_token":"demo-token-1","expires_in":3600,"token_type":"Bearer"} 200
$ curl -s -w ' %{http_code}\n' -H 'authorization: Bearer demo-token-1' localhost:7421/auth/me
{"user":"demo"} 200
$ curl -s -w ' %{http_code}\n' -X POST -H 'authorization: Bearer demo-token-1' localhost:7421/auth/logout
 204
$ curl -s -w ' %{http_code}\n' -H 'authorization: Bearer demo-token-1' localhost:7421/auth/me
{"error":"a valid bearer token is needed"} 401
```

The last four are test routes, for trying [`retry`](/vc-rs/reference/syntax/retry/), [`http.retry`](/vc-rs/reference/syntax/http-retry/), [`timeout`](/vc-rs/reference/syntax/timeout/), [`poll`](/vc-rs/reference/syntax/poll/) and [load tests](/vc-rs/reference/load/). Each refuses more than it is built for with `400` and a JSON `error`, never a quiet clamp: `ms` over `10000`, a key or ID over 64 bytes, a status outside `200`–`599`, a number in anything but the digits `0`–`9` (`+5`, `-1`, `1.5` or an empty value), or a request it cannot read, such as a path that is not UTF-8. `/flaky` and `/poll` each count up to 1024 keys; a new key past that is refused while the keys it has keep counting, until the demo restarts.

```console
$ curl -s -w ' %{http_code}\n' 'localhost:7421/flaky?key=pay&failTimes=1'
{"attempt":1} 503
$ curl -s -w ' %{http_code}\n' 'localhost:7421/flaky?key=pay&failTimes=1'
{"attempt":2} 200
$ curl -s -w ' %{http_code}\n' 'localhost:7421/poll/job?after=2'
{"attempt":1,"status":"pending"} 200
$ curl -s -w ' %{http_code}\n' 'localhost:7421/poll/job?after=2'
{"attempt":2,"status":"done"} 200
$ curl -s -w ' %{http_code}\n' -X POST localhost:7421/status/418
{"status":418} 418
$ curl -s -w ' %{http_code}\n' 'localhost:7421/slow?ms=20000'
{"error":"`ms` is at most 10000"} 400
```

```console
$ curl -s -X POST localhost:7421/echo -H 'content-type: application/json' -d '{"a":1}'
{"body":{"a":1},"headers":{"accept":"*/*","content-length":"7","content-type":"application/json","host":"localhost:7421","user-agent":"curl/8.7.1"},"method":"POST","path":"/echo","query":{}}
```

### Stop it

```console
$ vc demo stop
stopped the demo on port 7421
$ vc demo stop
no demo running on port 7421
```

Stopping when none runs is not an error. `stop` ends only a demo that `start --detach` started on that port, and only once every `start` that joined it has stopped. Two `start`s at the same moment leave one demo: they take turns, and the second joins the first.

The pidfile and the joins live in `vibranium-demo-<uid>` in the temp folder, which only you can open. When that folder is a link or belongs to another user, `start --detach` refuses (exit 2) and `stop` does not read it:

```console
$ vc demo start --detach
error: /tmp/vibranium-demo-501 is not a private folder of this user
  = help: remove it, so `vc demo start` can make it again
```

## Exit codes

| Code | When |
| --- | --- |
| `0` | Started, joined one already running, stopped, left running for another, or nothing to stop |
| `1` | The foreground demo ended with an error |
| `2` | A bad flag, `vc-demo` is not installed, another program holds the port, or the demo folder is not private to you |

`vc demo` runs a separate program, `vc-demo`. It looks in the folder `vc` is in, then on your `PATH`, and names both when it finds neither:

```console
$ vc demo start --detach
error: `vc-demo` is not next to vc (in /home/me/.cargo/bin) or on PATH
  = help: install it with `cargo install --git https://github.com/v007m/vc-rs vc-demo --locked`, or put `vc-demo` next to `vc`
$ vc demo start --port 99999
error: invalid value '99999' for '--port <PORT>': 99999 is not in 0..=65535

For more information, try '--help'.
```
