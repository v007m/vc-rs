A plugin is a program that `vc` starts to add a reporter or an auth type. `vc plugin add` shows what a plugin asks to reach, and on your approval installs it, adds it to the config and records the grant in `vibranium.lock`.

```console
$ vc plugin add [OPTIONS] <SOURCE>
$ vc plugin list [OPTIONS]
$ vc plugin remove [OPTIONS] <ID>
```

Every subcommand also takes [`--project`](/vc-rs/reference/cli/#global-flags).

## vc plugin add

| Flag | Value | Description |
| --- | --- | --- |
| `<SOURCE>` | | Where it comes from: `path:<folder>` or `npm:<package>[@<range>]` |
| `--yes` | | Approves what it asks to reach without asking. Needed when stdin is not a terminal, as in CI |

The folder must hold a [`vibranium-plugin.yaml`](/vc-rs/reference/plugins/manifest/):

```yaml title="plugins/summary/vibranium-plugin.yaml"
id: summary
version: 1.0.0
kind: reporter
entry:
  command: python3
  args: [report.py]
permissions:
  network: [reports.acme.io]
  secrets: [reportToken]
```

```console
$ vc plugin add path:plugins/summary
summary 1.0.0 · reporter plugin from path:plugins/summary (plugins/summary)
  runs: python3 report.py
  asks to reach: network reports.acme.io, secret reportToken
Approve? [y/N] y
✓ added plugin summary from path:plugins/summary
```

It copies the plugin into `.vibranium/plugins/summary/`, adds it to the config, and writes the lock:

```yaml title="vibranium.config.yaml"
plugins:
  - id: summary
    source: path:plugins/summary
```

```yaml title="vibranium.lock"
lockVersion: 1
plugins:
  - id: summary
    source: path:plugins/summary
    resolved: plugins/summary
    integrity: blake3-8405499700b5eb00f85cadc1e850a048987156522431221923a15b0cacff682c
    permissions:
      network: [reports.acme.io]
      secrets: [reportToken]
      files: []
```

Commit `vibranium.lock` and review changes to it like code. After you change the plugin, run `vc plugin add` again: the installed copy does not follow the source folder, and a run refuses a plugin that asks for more than the lock grants.

Without a terminal and without `--yes`, it shows the request and stops:

```console
$ vc plugin add path:plugins/summary </dev/null
summary 1.0.0 · reporter plugin from path:plugins/summary (plugins/summary)
  runs: python3 report.py
  asks to reach: network reports.acme.io, secret reportToken
error: cannot ask for approval: stdin is not a terminal
  = help: pass --yes to approve what it asks to reach
```

<Aside type="caution">
`vc` enforces the `secrets` a plugin may ask for. The `network` and `files` lists are shown and recorded but not enforced: a plugin runs with your user's rights. Add only plugins you trust. See [Permissions](/vc-rs/reference/plugins/permissions/).
</Aside>

## vc plugin list

```console
$ vc plugin list
summary  reporter 1.0.0  path:plugins/summary  ready  may reach: network reports.acme.io, secret reportToken
```

The columns are the ID, kind, version, source, state, and what it may reach. The state is `ready` when a run can use it; otherwise it says what is wrong and which command fixes it:

| State | Fix |
| --- | --- |
| `not installed` | `vc plugin add` it again |
| `not approved` | `vc plugin add` it |
| `asks for more: …` | `vc plugin add` it again |
| `not in the config` | `vc plugin remove` it |

With none, it prints ``no plugins; `vc plugin add <source>` adds one``.

## vc plugin remove

```console
$ vc plugin remove summary
✓ removed plugin summary
```

It removes the plugin from the config and the lock, and uninstalls the copy in `.vibranium/plugins/`. Your source folder stays.

## Exit codes

| Code | When |
| --- | --- |
| `0` | Added, listed or removed |
| `2` | Not approved, a bad source or manifest, or no such plugin |

```console
$ vc plugin add nope:x --yes
error: `nope:x` is not a plugin source
  = help: a plugin source is `npm:<package>[@<range>]` or `path:<folder>`
$ vc plugin add path:nope --yes
error: cannot fetch `path:nope`: /home/ada/shop/nope: No such file or directory (os error 2)
  = help: check the source; an `npm:` source needs `npm` on the path
$ vc plugin add path:plugins/bad --yes
error: the vibranium-plugin.yaml of `path:plugins/bad`: its id `Bad-Name` is not a camelCase word, such as `badName`
  = help: a plugin's vibranium-plugin.yaml has id, version, kind, entry.command and permissions
$ vc plugin remove summary
error: there is no plugin `summary`
  = help: `vc plugin list` lists them
```
