`${secret.NAME}` reads a secret. The name must be declared in `.env.schema`, and the value is masked as `••••` everywhere vc prints or stores it.

```yaml
    headers:
      authorization: Bearer ${secret.API_TOKEN}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `secret.<NAME>` | text | — | yes | Declared in `.env.schema` as a `NAME=` line. |

The value comes from the secrets provider. The default, `provider: env`, reads the process environment, and the project's `.env` fills the names it does not set.

```text title=".env.schema"
# The secret names this project uses, one NAME= line each, never their values.
DEMO_TOKEN=
```

```text title=".env (not committed)"
DEMO_TOKEN=s3cr3t-value
```

## Examples

A token in a header:

```yaml title="services/shop/shop.api.yaml"
headers:
  authorization: Bearer ${secret.SHOP_TOKEN}
```

The value is sent for real, and masked on the way back. This test sends the secret to the demo's `/echo` and then checks the echo against a wrong value on purpose:

```yaml title="services/tpl/secret.test.yaml"
tests:
  - id: sendsSecret
    call: sample#echo
    vars:
      payload:
        token: ${secret.DEMO_TOKEN}
    expect:
      body:
        match:
          body.token: wrong
```

```console
✕ tpl.s#sendsSecret                                               3ms
  error[V5101]: expect.body.match.body.token
    --> services/tpl/s.test.yaml:11:23
     |
  11 |           body.token: wrong
     |                       ^^^^^ expected "wrong", got "••••"
```

Inside other text, a secret still works: `Bearer ${secret.DEMO_TOKEN}` sends the whole string, and outputs show the secret part as `••••`.

## How it behaves

- Every secret value of four characters or more is masked in console output, reports, history and the JSON event stream, including inside response bodies.
- Secrets are not available in `$cel`. Set a var from the template and read the var instead, or better, keep secrets out of computed values.
- Reading a declared secret through `${env.NAME}` is V2107, because `env` values are not masked.

<Aside type="caution">
A secret that is declared but has no value is reported only when an action renders it: that action fails with V5111, and other tests still run.
</Aside>

## Common errors

A name that `.env.schema` does not declare:

```console
error[V2106]: `${secret.NOPE}` is not declared in `.env.schema`
 --> services/tpl/sec.test.yaml:5:16
  |
5 |       payload: ${secret.NOPE}
  |                ^^^^^^^^^^^^^^ NOPE is not in .env.schema
  = help: add the line `NOPE=` to `.env.schema` at the project root, or fix the name
```

A declared secret with no value, at run time:

```console
✕ tpl.s#readsUnsetSecret                                          0ms
  error[V5111]: `secret.MISSING_TOKEN` is missing: `secret` is {"DEMO_TOKEN":"••••"}
```

- [V2106](/vc-rs/reference/diagnostics/v2106/): the name is not in `.env.schema`.
- [V2107](/vc-rs/reference/diagnostics/v2107/): a declared secret read as `${env.NAME}`.
- [V5111](/vc-rs/reference/diagnostics/v5111/): the secret has no value at run time.
