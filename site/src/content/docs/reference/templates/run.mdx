`${run.…}` reads facts about the current run. Use it to tag data a run creates.

```yaml
    vars:
      name: user-${run.id}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `run.id` | number | — | — | The run's number in history. |
| `run.profiles` | list of text | — | — | The active profiles, in order. |
| `run.startedAt` | text | — | — | When the run started, as RFC 3339 in UTC: `2026-11-11T09:30:00.123Z`. |

## Examples

A run sent this payload:

```yaml
      payload:
        runId: ${run.id}
        profiles: ${run.profiles}
        startedAt: ${run.startedAt}
```

```json
{ "runId": 7, "profiles": ["default"], "startedAt": "2026-11-11T09:30:00.123Z" }
```

Inside text, the id becomes part of the string: `user-${run.id}` gives `"user-7"`.

## How it behaves

- `run` is available everywhere except `$cel`. Set a var from the template and read the var in CEL.

## Common errors

```console
✕ tpl.run#readsRunName                                             0ms
  error[V5111]: `run.name` is missing: `run` is {"id":40,"profiles":["default"],"startedAt":"2026-11-11T09:30:00.123Z"}
     = at: call sample#echo
```

- [V5111](/vc-rs/reference/diagnostics/v5111/): a field `run` does not have.
- [V2006](/vc-rs/reference/diagnostics/v2006/): `run` used as an id.
