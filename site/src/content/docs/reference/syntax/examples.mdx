`examples` turns one test into several test instances, one per row. Each row is a map. Its values are read with `${example.<column>}`.

```yaml
  - id: createsUsers
    examples:
      - email: ann@example.com
      - email: bob@example.com
    call: sample#createUser
    vars:
      email: ${example.email}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `examples` | list of maps | — | no | One test instance per row. Written on a test only. |
| `examples` | `${dataset.<name>}` | — | no | One row per dataset row. CSV columns become keys. |
| `examples` | `$file: <path>` | — | no | A YAML, JSON or CSV list in a file. The path is relative to the test file. |
| `${example.<column>}` | any value | — | — | The current row's value. Usable anywhere in the test. |

Select one row from the command line with `:n`, counting from 1: `vc run 'sample.rows#createsUsers:2'`.

## Examples

### Inline rows

Each row can hold any value, including a whole request body:

```yaml title="services/sample/rows.test.yaml"
id: sample.rows
name: Example rows

tests:
  - id: rejectsBadEmail
    name: Rejects a user without a usable email
    examples:
      - body: {name: No Email}
      - body: {name: Null Email, email: null}
    call: sample#createUser
    body: ${example.body}
    expect:
      status: 400

  - id: createsUsers
    name: Creates a user from each row
    examples:
      - email: ann@example.com
        name: Ann
      - email: bob@example.com
        name: Bob
    call: sample#createUser
    vars:
      email: ${example.email}
      name: ${example.name}
    expect:
      body:
        match:
          email: ${example.email}
```

`vc plan` lists one instance per row:

```console
$ vc plan sample.rows
plan  4 tests in 1 file · profile default
sample.rows
  sample.rows#rejectsBadEmail [row 1]
  sample.rows#rejectsBadEmail [row 2]
  sample.rows#createsUsers › Ann
  sample.rows#createsUsers › Bob
  sample.rows#createsFromDataset [row 1]
  sample.rows#createsFromDataset [row 2]
  sample.rows#createsFromFile [row 1]
  sample.rows#createsFromFile [row 2]
```

The header counts tests. The list shows instances. `vc plan` reads no secret or environment, so it names only the rows written in the test file, masked by your `redact` rules; rows from a dataset, `$file` or a template are named once they are read, when the test runs. Instances run in parallel, so they finish in any order. A row with a `name` is labeled by it (`› Ann`); a row without one by its number (`[row 2]`). The test's own `name` follows the label:

```console
$ vc run sample.rows
plan  4 tests in 1 file · profile default

✓ sample.rows#rejectsBadEmail [row 2] — Rejects a user without a usable email    4ms
✓ sample.rows#rejectsBadEmail [row 1] — Rejects a user without a usable email    4ms
✓ sample.rows#createsUsers › Ann — Creates a user from each row    4ms
✓ sample.rows#createsFromFile › Bob — Creates a user from each row of a file    4ms
✓ sample.rows#createsFromDataset › Bob — Creates a user from each dataset row    4ms
✓ sample.rows#createsFromDataset › Ann — Creates a user from each dataset row    4ms
✓ sample.rows#createsUsers › Bob — Creates a user from each row    4ms
✓ sample.rows#createsFromFile › Ann — Creates a user from each row of a file    4ms

8 passed                                                     7ms · profile default
```

### Rows from a dataset

A dataset gives one row per CSV line. The header names the columns:

```text title="datasets/people.csv"
email,name
ann@example.com,Ann
bob@example.com,Bob
```

```yaml
  - id: createsFromDataset
    name: Creates a user from each dataset row
    examples: ${dataset.people}
    call: sample#createUser
    vars:
      email: ${example.email}
      name: ${example.name}
```

### Rows from a file

`$file` reads a list from a file next to the test:

```yaml title="services/sample/rows.yaml"
- email: ann@example.com
  name: Ann
- email: bob@example.com
  name: Bob
```

```yaml
  - id: createsFromFile
    name: Creates a user from each row of a file
    examples:
      $file: rows.yaml
    call: sample#createUser
    vars:
      email: ${example.email}
      name: ${example.name}
```

### Run one row

Add `:n` to a test ID to run only that row:

```console
$ vc run 'sample.rows#createsUsers:2'
plan  1 test in 1 file · profile default

✓ sample.rows#createsUsers › Bob — Creates a user from each row    3ms

1 passed                                                     4ms · profile default
```

### Rows and repeat together

A test with both `examples` and [`repeat`](/vc-rs/reference/syntax/repeat/) runs every row that many times. With two rows and `repeat: 2`, the instances are `[row 1, repeat 1]`, `[row 1, repeat 2]`, `[row 2, repeat 1]` and `[row 2, repeat 2]`. The `:n` selector counts them in that order, so `:3` is row 2, repeat 1.

## How it behaves

- Each row is its own test instance. It gets its own `beforeEach`, `before`, cleanups and report entry.
- Instances of one test run in parallel, like any other tests, up to `defaults.concurrency`.
- `vc check` knows the columns of inline rows. A misspelled `${example.*}` is an error before the run.
- A `$file` path is relative to the test file, not the project root.
- A row's `name` key is a column like any other, and it also labels the row's instance in reports: `sample.rows#createsUsers › Ann`. A row read from a `$file` is labeled the same way. Rows of one test that share a `name` keep their numbers too, so no two labels match: `› Bob [row 1]` and `› Bob [row 3]`. A row without a `name`, or whose `name` is not plain text, is labeled by its number: `[row 1]`, `[row 2]` and so on. An inline row's `name` labels it only when written as plain text; a `${…}` in it is not rendered for the label. A `name` that holds a secret's value, such as a dataset row named with a token, is masked: `› ••••`. `vc plan` lists every row by its number.

<Aside type="note">
`examples` written as one template, such as `${var.rows}` or `${dataset.people | shuffle | take(3)}`, is read once before the run starts, under the run's profiles and `--set`. It reads only `var`, `env` and `dataset` (anything else is [V2105](/vc-rs/reference/diagnostics/v2105/)), and `--seed` repeats a `shuffle`. Rows that are not a list of maps stop the run with [V5111](/vc-rs/reference/diagnostics/v5111/). Inline rows are rendered per instance and may read any root, `secret` included; reports name an instance by its row's `name` when it gives one as plain text, otherwise by its row number, never by its other values.
</Aside>

## Common errors

A column that no row has:

```console
error[V2103]: ${example.mail} names no column of this test's examples
 --> services/sample/rowerr.test.yaml:7:14
  |
4 |       - email: ann@example.com
  |       ------------------------ the rows
...
7 |       email: ${example.mail}
  |              ^^^^^^^^^^^^^^^ no row has `mail`
  = help: the columns are `email`
  = help: did you mean `email`?
  = fix: Replace with email (certain)
```

`${example.*}` in a test without `examples`:

```console
error[V2102]: `example` is not available here
  --> services/sample/rowerr.test.yaml:11:10
   |
11 |       q: ${example.email}
   |          ^^^^^^^^^^^^^^^^
   = help: `example` is available only in a test with examples
```

A row number past the last row. `vc run` exits with 2:

```console
$ vc run 'sample.rows#createsUsers:5'
error: `sample.rows#createsUsers:5` asks for an instance the test does not have; it has 2
  = help: pick an instance from 1 to 2
```

- [V2103](/vc-rs/reference/diagnostics/v2103/): the column is not in the rows.
- [V2102](/vc-rs/reference/diagnostics/v2102/): `example` used outside a test with `examples`.
