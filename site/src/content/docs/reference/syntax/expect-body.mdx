`expect.body` checks the response body. Use `match` for values at paths, `equals` for the whole body, and `schema` for its shape.

```yaml
expect:
  body:
    match:
      id:
        type: string
      name: Ada Lovelace
```

This page covers checks on the **response**. To send a request body, see [body](/vc-rs/reference/syntax/body/).

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `body.match` | map of path to literal or matcher | none | no | Each path is its own check. Values can use templates. |
| `body.equals` | any value | none | no | The whole body must equal it, compared deeply. |
| `body.schema` | JSON Schema, or `$file: <path>` | none | no | The path is relative to the file that holds it. |

The three can be used together. All of them run, and each failure is reported on its own.

### Paths in `match`

| Path | Reads |
| --- | --- |
| `id` | the top-level field `id` |
| `user.address.city` | a nested field |
| `tags[0]` | the first item of a list |
| `tags[-1]` | the last item |
| `tags[*]` | every item, as a list |
| `[0]`, `[*].id` | items of a body that is itself a list (quote these keys in YAML) |
| `headers["user-agent"]` | a field whose name has a dash or a dot |

### Literal or matcher

A value is a **matcher** when it is a map and at least one of its keys is a matcher name, such as `type`, `contains` or `every` (see [Matchers](/vc-rs/reference/matchers/)). Several matchers in one map must all pass.

Anything else is a **literal**, and the value at the path must equal it exactly. That includes a map with no matcher key: it is compared deeply, so the object at that path must have exactly those fields.

## Examples

**Values at paths.** The echo api returns what it was sent. These checks all pass:

```yaml
expect:
  body:
    match:
      method: POST
      body.name: Ada
      body.tags[0]: a
      body.tags[-1]: b
      body.tags[*]:
        every:
          in: [a, b]
      headers["user-agent"]:
        startsWith: vibranium
      query:
        empty: true
```

Each failing path is its own error, with the expected and the actual value:

```console
✕ lab.fails#badMatch                                              3ms
  error[V5101]: expect.body.match.body.name
    --> services/lab/fails.test.yaml:19:22
     |
  19 |           body.name: Grace
     |                      ^^^^^ expected "Grace", got "Ada"
  error[V5101]: expect.body.match.body.tags
    --> services/lab/fails.test.yaml:21:13
     |
  21 |             length: 5
     |             ^^^^^^^^^ expected {"length":5}, got ["a","b"]
```

A path that is not in the body reports `got nothing`. Only `exists: false` passes there.

**A body that is a list.** Quote the keys that start with `[`.

```yaml
- id: listUsers
  call: users#list
  expect:
    body:
      match:
        "[*].id":
          every:
            type: string
        "[0]":
          id: "1"
          name: Ada Lovelace
```

**A value from a var.** Literals can be templates.

```yaml
- id: templated
  call: echo#json
  vars:
    name: Grace
  expect:
    body:
      match:
        body.name: ${var.name}
```

**The whole body.** `equals` fails on any extra or missing field.

```yaml
- id: wholeBody
  call: users#get
  vars:
    userId: "1"
  expect:
    body:
      equals:
        id: "1"
        name: Ada Lovelace
```

A failure prints a diff of the expected and the actual body:

```console
✕ lab.fails#badEquals                                             4ms
  error[V5101]: expect.body.equals
    --> services/lab/fails.test.yaml:30:11
     |
  30 |           method: POST
     |           ^^^^^^^^^^^^ expected {"method":"POST"}, got {"body":"plain words", ...}
     = diff:
       --- expected
       +++ actual
       @@ -1,3 +1,15 @@
        {
       -  "method": "POST"
       +  "body": "plain words",
       +  "headers": {
       ...
```

**A JSON Schema, from a file or inline.**

```yaml
expect:
  body:
    schema:
      $file: ../../schemas/user.json
```

```yaml
expect:
  body:
    schema:
      type: object
      required: [id, name]
      properties:
        id:
          type: string
        name:
          type: string
```

A failure names the JSON pointer and the rule that failed:

```console
✕ lab.fails#badSchema                                             4ms
  error[V5101]: expect.body.schema
    --> services/lab/fails.test.yaml:36:11
     |
  36 |           $file: ../../schemas/echo.json
     |           ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ /body/word: value is not of type "integer"
```

## How it behaves

- **Merging.** Each `match` path is its own check, keyed by the path as written. A more specific level replaces the check for the same path only. `equals` and `schema` are one check each.
- **Paths are compared as written.** `body: { word: hi }` is the path `body` with a literal map, and `body.word: hi` is the path `body.word`. They are different checks, so both run. The first also requires `body` to have no other fields.
- **`[*]` yields a list.** Use a list matcher on it: `every`, `some`, `none`, `length` or `contains`.
- **Templates.** `match` and `equals` values can use `${…}`. Schema files are read as written.

<Aside type="caution">
Some mistakes are not caught by `vc check` yet and only fail at run time:

- A misspelt matcher that is alone in its map, such as `{ startWith: A }`, is read as a literal map and fails with `expected {"startWith":"A"}, got "Ada"`. When its name is close to a matcher's, `vc check` warns [V3208](/vc-rs/reference/diagnostics/v3208/); next to a real matcher it is the error [V1004](/vc-rs/reference/diagnostics/v1004/).
- A scalar matcher on a `[*]` path, such as `tags[*]: { gt: 1 }`, is the error [V2306](/vc-rs/reference/diagnostics/v2306/); wrap it in `every` or `some`.
- A schema file that is not a valid JSON Schema fails with `is not a valid JSON Schema`.
- A JSONPath-style `$.id` is read as a field named `$` and reports `got nothing`. Write `id`.
</Aside>

## Common errors

| Code | When |
| --- | --- |
| [V1004](/vc-rs/reference/diagnostics/v1004/) | An unknown key under `body`, or an unknown matcher next to a known one. |
| [V2306](/vc-rs/reference/diagnostics/v2306/) | A matcher argument is invalid: a `type` that is not a JSON type, a `format` that is not known, or a regex that does not compile. |
| [V2004](/vc-rs/reference/diagnostics/v2004/) | The `$file` of a schema is not in the project. |
| [V2101](/vc-rs/reference/diagnostics/v2101/) | A template reads a var that no level sets. |
| [V5101](/vc-rs/reference/diagnostics/v5101/) | A body check failed at run time. |
