`path` is the end of an api's URL. vc puts the file's [`baseUrl`](/vc-rs/reference/syntax/base-url/) in front of it, exactly as written.

```yaml title="services/sample/sample.api.yaml"
baseUrl: ${var.sampleUrl}
apis:
  - id: getUser
    path: /users/${var.userId}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `path` | template | — | yes | Start it with `/`. Joined to `baseUrl` as plain text. Each `${…}` value is percent-encoded as one segment. |

The query string does not go in `path`. Put it in [`query`](/vc-rs/reference/syntax/query/), which encodes each value for you.

## Examples

### A path with a var

`getUser` reads the user whose ID is in `userId`. Any caller can set it.

```yaml title="services/sample/sample.api.yaml"
  - id: getUser
    name: Get a user
    path: /users/${var.userId}
```

```console
$ vc call sample#getUser --var userId=1
200 OK · 27 ms · api expect passed
{
  "id": "1",
  "name": "Ada Lovelace"
}
```

In a test, the var usually comes from an earlier call's [`save`](/vc-rs/reference/syntax/save/), such as `userId: ${response.body.id}` on `createUser`.

### Values are encoded as one segment

vc percent-encodes each `${…}` value in the path, so whatever it holds stays one path segment. A space is sent as
`%20` and a `/` as `%2F`, and a `..` cannot climb to another endpoint. The text you write around the values is sent
as written.

```yaml title="services/req/req.api.yaml"
  - id: getUser
    path: /users/${var.userId}
    vars:
      userId: "1"
```

```console
$ vc call req#getUser
200 OK · 12 ms · api expect passed
{
  "id": "1",
  "name": "Ada Lovelace"
}
```

With `userId: a b/c` the same api sends `/users/a%20b%2Fc`, one path segment. The demo has no such user, so it answers 404:

```console
$ vc call req#getUser --var "userId=a b/c"
404 Not Found · 2 ms · api expect failed
✗ status: expected ["2xx"], got 404
```

Don't add the [`urlEncode`](/vc-rs/reference/pipes/url-encode/) pipe. A value whose last pipe is `urlEncode` is sent as
the pipe left it, not encoded twice, and `vc check` warns with [V4007](/vc-rs/reference/diagnostics/v4007/), whose fix
removes the pipe.

### A full URL in the path

An api file without a `baseUrl` can put a whole URL in `path`. This suits a one-off endpoint on another host.

```yaml title="services/nobase/nobase.api.yaml"
apis:
  - id: full
    path: http://localhost:7432/echo
```

```console
$ vc call nobase#full
200 OK · 8 ms · api expect passed
{
  "body": null,
  "headers": {
    "accept": "application/json",
    "accept-encoding": "gzip, br, zstd, deflate",
    "host": "localhost:7432",
    "user-agent": "vibranium/2"
  },
  "method": "GET",
  "path": "/echo",
  "query": {}
}
```

### Check the URL before you send it

`vc explain` prints the joined URL with the vars filled in:

```console
$ vc explain req#put
req#put
profile  default
  PUT http://localhost:7432/echo/abc 123
```

`vc explain` shows each value as it renders, before it is encoded: the call sends `/echo/abc%20123`. A template with a pipe is shown unrendered, as in `GET http://localhost:7432/users/${var.userId | trim}`.

## How it behaves

- The URL is `baseUrl` followed by `path`, joined as plain text. vc adds no `/` and removes none.
- A path without a leading `/` runs into the host. With `baseUrl` `http://localhost:7432` and `path: echo`, the URL is `http://localhost:7432echo`. `vc check` warns with [V4005](/vc-rs/reference/diagnostics/v4005/), and `vc check --fix` adds the `/`. See below.
- A `baseUrl` that ends in `/` plus a path that starts with `/` gives `//`, which most servers answer with 404. `vc check` warns with V4005 here too.
- A path that is a full URL or starts with a template (`${var.usersUrl}/users`) is not checked.
- A path parameter is a var: `/poll/${var.jobId}`. The OpenAPI style `/poll/{jobId}` is sent as the literal text `{jobId}`, so `vc check` warns with [V4006](/vc-rs/reference/diagnostics/v4006/) and suggests the var.
- Each `${…}` value is percent-encoded as one segment: `/`, `?`, `#`, `%` and a space are encoded, while letters, digits and `-._~!$&'()*+,;=:@` are kept. A value that is just `.` or `..` is sent as `%2E` or `%2E%2E`. Values in [`query`](/vc-rs/reference/syntax/query/) are encoded too, so neither needs `urlEncode` (V4007 warns about it in a path).
- A value before the path's first `/` that is an absolute `http://` or `https://` URL, such as `${var.usersUrl}` in `${var.usersUrl}/users`, is the start of a URL and is sent as written, as `baseUrl` is. Any other value there is one segment like the rest: `${var.id}/orders` with `id: ../admin` sends `..%2Fadmin/orders`.
- Any var in scope can be used: the api's own `vars`, the file's, the config's, a test's, or a saved value.

## Common errors

A missing leading slash is a V4005 warning. Left as it is, the run fails: `7432echo` is not a port, so vc ends up
connecting to port 80:

```yaml title="services/h/h.api.yaml"
  - id: noSlash
    path: echo
```

```console
$ vc check
warning[V4005]: `path` does not start with `/`
  = help: start it with `/`: `path: /echo`
  = fix: Add the leading `/` (certain)

$ vc explain h#noSlash
h#noSlash
profile  default
  GET http://localhost:7432echo

$ vc run h.t
✕ h.t#c                                                           4ms
  error[V5105]: cannot connect to localhost:80: Connection refused (os error 61)
     = at: call h#noSlash
```

An OpenAPI-style placeholder is a V4006 warning, with a suggested fix:

```console
$ vc check
warning[V4006]: `{jobId}` in a `path` is sent as is; it is not a var
  = help: write each one as a var: `${var.jobId}`, and set it in the test's `vars`
  = fix: Write each placeholder as a var
```

A path var that no level sets fails `vc check` with [V2101](/vc-rs/reference/diagnostics/v2101/). A path that is not a valid URL fails the call with [V5111](/vc-rs/reference/diagnostics/v5111/). A host that refuses the connection fails with [V5105](/vc-rs/reference/diagnostics/v5105/).
