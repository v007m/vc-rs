The `test:` action runs another test's call or steps in place, so one flow can be shared by many tests.

```yaml title="services/flow/reuse.test.yaml"
tests:
  - id: reusesInSteps
    steps:
      - test: shared.flows#memberWithEcho
      - call: sample#getUser
```

## Syntax

`test` takes a full test ID: `<fileId>#<id>`. It is an action, so it can be a step, or an entry in [`before`](/vc-rs/reference/syntax/before/), `after`, [`beforeEach`](/vc-rs/reference/syntax/before-each/) or [`beforeAll`](/vc-rs/reference/syntax/before-all/).

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `test` | test ID | — | yes | The test to run. Usually one marked [`standalone: false`](/vc-rs/reference/syntax/standalone/). |
| `id` | camelCase | — | in `beforeAll` | Shares the saved values as `${var.<id>.<name>}`. Required in `beforeAll` and `beforeRun` when the test saves values. |
| `vars` | map | — | no | Vars passed into the reused test. |
| `provides` | list | — | no | The names the reused test saves that later steps read. See [provides](/vc-rs/reference/syntax/provides/). |
| `timeout` | duration | — | no | The limit on all of its calls together. |
| `auth`, `headers`, `query`, `body`, `expect`, `save`, `poll`, `retry`, `keep`, `cache`, `repeat`, `forEach`, `parallel` | | | no | As on [`call`](/vc-rs/reference/syntax/call/). |

## Examples

### A shared flow

Put the flow in its own file and mark it `standalone: false`, so it only runs when reused.

```yaml title="services/shared/flows.test.yaml"
id: shared.flows
name: Reusable flows
tests:
  - id: memberWithEcho
    name: Create a member, then echo its id
    standalone: false
    steps:
      - call: sample#createUser
        vars:
          email: member@example.com
      - call: echo#json
        vars:
          name: ${var.userId}
        save:
          echoedName: ${response.body.body.name}
```

### Reusing it as a step

The values the flow saves are visible to the later steps. List them in `provides` so the dependency is explicit.

```yaml title="services/flow/reuse2.test.yaml"
id: flow.reuse2
tests:
  - id: readsDeclared
    steps:
      - test: shared.flows#memberWithEcho
        provides: [echoedName, userId]
      - call: echo#json
        vars:
          name: ${var.echoedName}
        expect:
          body:
            match:
              body.name: ${var.userId}
```

```console
$ vc run flow.reuse2
plan  1 test in 1 file · profile default

✓ flow.reuse2#readsDeclared                                       4ms

1 passed                                                     5ms · profile default
```

Without `provides`, the run still passes, but warns once per value:

```console
! V5108: `var.echoedName` was saved by a `test:` step that does not declare it; add `provides: [echoedName]` to that step
! V5108: `var.userId` was saved by a `test:` step that does not declare it; add `provides: [userId]` to that step
```

### Reusing it once per file

In `beforeAll`, the flow runs once for the whole file. Give it an `id`; its values are read as `${var.<id>.<name>}`.

```yaml title="services/flow/reuse.test.yaml"
id: flow.reuse
beforeAll:
  - id: shared
    test: shared.flows#memberWithEcho
tests:
  - id: readsSharedMember
    call: sample#getUser
    vars:
      userId: ${var.shared.userId}
    expect:
      status: 200
```

`vc plan` shows which tests need it:

```console
$ vc plan flow.reuse
plan  2 tests in 1 file · lifecycle: beforeAll shared · profile default
flow.reuse
  beforeAll
    shared
  flow.reuse#readsSharedMember  needs: shared
  flow.reuse#reusesInSteps
```

If the shared flow fails, only the tests that read it are blocked, with the flow's error:

```console
⊘ flow.reuse#readsSharedMember blocked
```

## How it behaves

- The reused test's own steps run, with its own step defaults. Its test-level `expect` is applied to its steps, the same as when it runs on its own. The calling test's step defaults do not reach them.
- Values the reused test saves become vars of the caller. In `beforeAll` and `beforeRun` they are shared under the action's `id` instead.
- Cleanups the reused test registers belong to the caller. As a step they run after the calling test; in `beforeAll` they run after the file's last test.
- A test can be reused from any file. Reuse is checked at compile time: a cycle (a test that reuses itself, directly or through others) is an error.
- `timeout` on a `test` action limits all its calls together, not each one.

A reused test with `expect: {status: 418}` fails the caller with `expected [418], got 201`. Put checks you want only on standalone runs in a separate test.

## Common errors

An unknown test ID fails `vc check`:

```console
error[V2003]: unknown test "shared.flows#nope"
```

A `beforeAll` action that saves values needs an `id`:

```console
error[V2210]: this beforeAll action saves values but has no `id`
 --> services/flow/noid.test.yaml:3:5
  |
3 |   - call: sample#createUser
  |     ^^^^ needs an `id`
  = help: shared values are read as `${var.<id>.<name>}`; give the action an `id`
  = fix: Add id: createUser (certain)
```

A test that reuses itself, directly or through other tests, is a cycle:

```console
error[V2205]: `test:` reuse forms a cycle: flow.cycle#pingsA → flow.cycle#pingsB → flow.cycle#pingsA
  --> services/flow/cycle.test.yaml:10:15
   |
10 |       - test: flow.cycle#pingsA
   |               ^^^^^^^^^^^^^^^^^ this reuse closes the cycle
   = help: a test cannot reuse itself, directly or through other tests; move the shared steps into one test
```

See [V2003](/vc-rs/reference/diagnostics/v2003/), [V2205](/vc-rs/reference/diagnostics/v2205/), [V2210](/vc-rs/reference/diagnostics/v2210/) and [V5108](/vc-rs/reference/diagnostics/v5108/).
