`type` says what an api speaks. Set it on an api file as the default for every api in it, or on one api, whose own value wins. Leave it out and the api is `http`, so a file that sets none keeps its meaning.

```yaml title="services/users/users.api.yaml"
type: http
baseUrl: ${var.baseUrl}
apis:
  - id: getUser
    path: /users/${var.userId}
```

## Syntax

| Field | Type | Default | Required | Notes |
| --- | --- | --- | --- | --- |
| `type` | `http`, `graphql`, `sse`, `websocket` | `http` | no | On the api file, the default for its apis |
| `type` | `http`, `graphql`, `sse`, `websocket` | the file's, else `http` | no | On an `apis` entry; wins over the file's |

`type` belongs to the api. A test or step that calls it uses the api's type and can't set its own.

| Type | Speaks | Needs | Keys it does not take |
| --- | --- | --- | --- |
| `http` | HTTP requests as written | `path` | `expect.errors`; an `sse` block |
| `graphql` | one GraphQL operation as a JSON `POST`; see [`graphql`](/vc-rs/reference/syntax/graphql/) | `body.query` | `method` on the api; `body` on a test or step that calls it |
| `sse` | server-sent events read from one request's streamed response | `path` | `expect.errors`; `poll` on a test or step that calls it |
| `websocket` | messages over one WebSocket connection, opened with a `GET` | `path` | `method`, `body` and an `sse` block on the api; `expect.errors`; `body` and `poll` on a test or step that calls it |

`sse` and `websocket` are checked today, but their calls are not run yet: a call of one fails before anything is sent. The other types (JSON-RPC, gRPC) follow in their own issues.

An `sse` api, or a `type: sse` file for all of its apis, may set `sse.reconnect: true`: when the stream ends early the call opens it once more, sending `last-event-id`. It is `false` when left out, and an `sse` block anywhere else is V2213.

## Examples

### Set once for the file

Every api in the file takes the file's `type`, and writing `type: http` changes nothing: the file compiles exactly as it would without it.

```yaml title="services/orders/orders.api.yaml"
type: http
baseUrl: ${var.baseUrl}
apis:
  - id: listOrders
    path: /orders
  - id: placeOrder
    method: POST
    path: /orders
    body: {sku: A-1, quantity: 1}
```

### A GraphQL file

A `type: graphql` file's apis send their `body.query` to `/graphql` (or the file's [`graphql.path`](/vc-rs/reference/syntax/graphql/)) as a `POST`.

```yaml title="services/accounts/accounts.api.yaml"
type: graphql
baseUrl: ${var.baseUrl}
apis:
  - id: getUser
    body:
      query: 'query GetUser($id: ID!) { user(id: $id) { id name } }'
      variables:
        id: ${var.userId}
```

### A stream file

A `type: sse` file's block applies to each of its `sse` apis; an api with its own type, here `websocket`, takes none of it.

```yaml title="services/feed/feed.api.yaml"
type: sse
baseUrl: ${var.baseUrl}
sse:
  reconnect: true
apis:
  - id: prices
    path: /prices
  - id: chat
    type: websocket
    path: /chat
```

### Set on one api

An api's own `type` wins over its file's.

```yaml title="services/health/health.api.yaml"
baseUrl: ${var.baseUrl}
apis:
  - id: ping
    type: http
    path: /health
```

## How it behaves

- The type is read once, when the file is checked: an api's own `type`, else its file's, else `http`. A value that is not a known type counts as unset, so it falls back the same way.
- The type decides which keys apply: on the api, in its `expect`, and on a test or step that calls it (in its `expect` and `poll.until` too, and on a `cache.check` call inside it). A key the type does not use is an error, V2213, whose fix removes the key. `http` uses every key but `expect.errors` and an `sse` block.
- Each type needs its own keys: an `http`, `sse` or `websocket` api without `path`, or a `graphql` api without `body.query`, is V1005.
- A value that is not a known type is V2302, with the close type as its fix.

```yaml wrong V2302 title="services/billing/billing.api.yaml"
baseUrl: ${var.baseUrl}
apis:
  - id: listInvoices
    type: htp
    path: /invoices
```

```console
$ vc check services/billing
error[V2302]: expected one of http, graphql, sse, websocket, found `htp`
```

## Common errors

| Code | When |
| --- | --- |
| [V2302](/vc-rs/reference/diagnostics/v2302/) | `type` is not a known type |
| [V2213](/vc-rs/reference/diagnostics/v2213/) | A key that does not apply to the api's type |
| [V1005](/vc-rs/reference/diagnostics/v1005/) | A key the api's type needs is missing |
