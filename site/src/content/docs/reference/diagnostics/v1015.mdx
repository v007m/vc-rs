A `type: graphql` api file's `graphql.schema` names the schema its documents are checked against: an SDL file
(`.graphql`, `.gql` or `.graphqls`) that holds only type definitions, or a `.json` file that holds the answer to an
introspection query, `{"data": {"__schema": …}}` or `{"__schema": …}`. V1015 is a file that reads but is not a
schema: SDL that holds an operation or a fragment, or that does not validate (a type it uses but never defines, a
type with nothing in it, no `Query` type); or JSON without `__schema`, without its `types` list, or with a type that
is not what an introspection result holds there, such as a type kind that is not one or an object with no fields.
The diagnostic points at the definition or the JSON value that is wrong. A syntax error in an SDL file is V1014, as
in any GraphQL file.

## Wrong

```yaml wrong V1015 title="services/catalog/catalog.api.yaml"
type: graphql
graphql:
  schema: {$file: schema.json}
apis:
  - id: getProduct
    body:
      query: "query GetProduct($id: ID!) { product(id: $id) { id name } }"
      variables: {id: p1}
```

```json wrong V1015 title="services/catalog/schema.json"
{"openapi": "3.1.0", "paths": {}}
```

## Right

```yaml title="services/catalog/catalog.api.yaml"
type: graphql
graphql:
  schema: {$file: schema.graphql}
apis:
  - id: getProduct
    body:
      query: "query GetProduct($id: ID!) { product(id: $id) { id name } }"
      variables: {id: p1}
```

```graphql title="services/catalog/schema.graphql"
type Query {
  product(id: ID!): Product
}

type Product {
  id: ID!
  name: String
}
```
