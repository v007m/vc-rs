The server ended the TLS handshake with an alert about the client certificate: `certificate_required` (none was
sent), `bad_certificate`, `unknown_ca` (it doesn't trust the issuer), `certificate_expired`, `certificate_revoked`,
`unsupported_certificate` or `access_denied` (often a valid certificate the server doesn't allow). Only that call
fails. The message names the alert and the identity that was sent, never its key. When none was sent, any of these
alerts means the server asks for one; with `clientCert: none` the message says certificates are off for the call. Here the server asks for a certificate and the project sends none; give the host an
`http.tls.clients` entry, or put a `clientCert` on the auth the call uses.

## Wrong

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
```

```yaml title="services/payments/payments.api.yaml"
baseUrl: https://payments.internal.example
apis:
  - id: listPayments
    path: /payments
```

## Right

```yaml skip title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: paymentsClient
        hosts: [payments.internal.example]
        cert: certs/payments-client.pem
        key: certs/payments-client.key
```

```yaml skip title="services/payments/payments.api.yaml"
baseUrl: https://payments.internal.example
apis:
  - id: listPayments
    path: /payments
```
