A header in an api file's `source.headers` that carries a credential (`authorization`, a cookie, an api key, a
token, …) is written as the value itself, so the token is committed to git with the file. Write it as
`${secret.NAME}` instead: `vc sync` reads the value from `.env` (or the secrets provider) when it fetches the
spec, and the file keeps only the name. `vc import openapi --header` refuses the same header up front.

## Wrong

```yaml title="services/users/users.api.yaml"
baseUrl: https://api.example.com
source:
  openapi: https://specs.example.com/users.yaml
  headers:
    authorization: Bearer eyJhbGciOiJIUzI1NiJ9
apis:
  - id: listUsers
    path: /users
```

## Right

```dotenv title=".env.schema"
# the token the spec server takes
SPEC_TOKEN=
```

```yaml title="services/users/users.api.yaml"
baseUrl: https://api.example.com
source:
  openapi: https://specs.example.com/users.yaml
  headers:
    authorization: Bearer ${secret.SPEC_TOKEN}
apis:
  - id: listUsers
    path: /users
```
