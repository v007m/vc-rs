A schedule's `cron` says when `vc ui`'s server starts its run, and an exported GitHub Actions
workflow carries it over unchanged, so it is the five-field cron both read: minute (0-59), hour
(0-23), day of the month (1-31), month (1-12) and day of the week (0-7, where 0 and 7 are
Sunday), in UTC. Each field is `*`, a number, a range `a-b`, a step `*/n` or `a-b/n`, or a list of
those joined with `,`. Names such as `MON` or `JAN`, a sixth seconds field and shortcuts such as
`@daily` are not read: a schedule written with them would never run. The label says which field
is wrong. When both day fields are restricted, a day that matches either one fires.

## Wrong

```yaml wrong V2317 title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
schedules:
  - id: nightlySmoke
    cron: "0 25 * * MON-FRI"
```

## Right

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
schedules:
  - id: nightlySmoke
    cron: "0 2 * * 1-5"
```
