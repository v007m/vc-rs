`vc check` looked at each `plugins` item the way a run does before it starts the plugin, and a run would leave this
one out. `vibranium.lock` cannot be read or does not approve the plugin, it is not installed under
`.vibranium/plugins/<id>/`, its installed manifest asks for more than the lock grants, or its `config` holds a `${…}`
value. A plugin's `config` takes literal values only, so it can never carry a secret the lock did not grant; the plugin
reads a granted secret with `secrets/get`. The run warns the same way and goes on: the work that needs the plugin fails,
and a reporter's report is not written. `vc plugin list` shows each plugin's state; `vc plugin add <source>` installs
one and approves what it asks for.

## Wrong

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
plugins:
  - id: summary
    source: path:plugins/summary
    config: {url: "${var.reportUrl}"}
```

## Right

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
plugins:
  - id: summary
    source: path:plugins/summary
    config: {url: https://reports.example.com/upload}
```
