`vc check` reads each `http.tls.clients` certificate the config writes as text, a `cert` or a `pkcs12` bundle, and
warns when today, in UTC, is after the day it expires or before the day it starts. A server refuses such a
certificate at the handshake (V5127). That is fine for a test that expects the refusal; otherwise renew it, or check
the clock of the machine that issued it. Only the client's own certificate is dated, not the rest of its chain and
not the `ca` roots. A run says the same, in a warning at its end, about each certificate its profiles present, one
whose path or text is rendered from a `${…}` too.

## Wrong

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: paymentsClient
        hosts: [payments.internal.example]
        cert: certs/payments-client-2025.pem
        key: certs/payments-client-2025.key
```

## Right

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: paymentsClient
        hosts: [payments.internal.example]
        cert: certs/payments-client-2027.pem
        key: certs/payments-client-2027.key
```
