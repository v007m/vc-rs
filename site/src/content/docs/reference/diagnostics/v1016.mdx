An `http.tls.clients` entry is one client certificate, and it comes from one place: `cert` and `key`, each a PEM
file or inline PEM, or `pkcs12`, a PKCS#12 bundle (`.p12`, `.pfx`) with its `passphrase`. An entry that writes
`pkcs12` beside `cert` or `key` leaves it unclear which certificate is meant, and an entry that writes none of them
has no certificate to send. The check cannot know which one you meant, so it offers no fix.

## Wrong

```yaml wrong V1016 title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: partnerClient
        hosts: [api.partner.example]
        cert: certs/partner.crt
        key: certs/partner.key
        pkcs12: certs/partner.p12
```

## Right

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: partnerClient
        hosts: [api.partner.example]
        cert: certs/partner.crt
        key: certs/partner.key
```
