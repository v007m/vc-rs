A `skip` has no reason: it is blank, or `true` or `false`. The reason shows in every report next to the skipped test,
so that nobody has to guess why it is parked; write it as `skip: <reason>` or `skip: {reason: ..., until: ...}`. To run
the test again, delete `skip`.

## Wrong

```yaml wrong V3103 title="services/users/users.api.yaml"
apis:
  - id: getUser
    path: /users/1
```

```yaml wrong V3103 title="services/users/crud.test.yaml"
tests:
  - id: getsUser
    call: users#getUser
    skip: true
```

## Right

```yaml title="services/users/users.api.yaml"
apis:
  - id: getUser
    path: /users/1
```

```yaml title="services/users/crud.test.yaml"
tests:
  - id: getsUser
    call: users#getUser
    skip: flaky upstream, see issue 212
```

## Seen in practice

This is real output from `vc`, run against the files below.

```yaml wrong V3103 title="services/users/users.api.yaml"
apis:
  - id: listUsers
    path: /users
```

```yaml wrong V3103 title="services/users/crud.test.yaml"
id: users.crud
name: Users CRUD
tests:
  - id: listsUsers
    name: Lists users
    call: users#listUsers
    skip: ''
```

```console
$ vc check
error[V3103]: `skip` needs a reason
 --> services/users/crud.test.yaml:7:11
  |
7 |     skip: ''
  |           ^^ no reason given
  = help: say why, for the report: `skip: flaky upstream, see #123`

1 error · 0 warnings · 3 files checked
$ echo $?
2
```
