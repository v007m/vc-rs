A `clients` entry in `http.tls` loaded, but its parts do not make one identity: the `key` is not the private key of
the `cert`, or a `pkcs12` bundle's `passphrase` is wrong, or the bundle holds no key, or none of its certificates goes
with its key. The run stops before any request, with exit code 2, since every call to the entry's hosts would be
refused at the handshake. The message names the entry and what does not fit, never the key or the passphrase. Use the
key issued with the certificate, or the bundle's own passphrase. Here `key` belongs to another certificate.

## Wrong

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: paymentsClient
        hosts: [payments.internal.example]
        cert: certs/payments-client.pem
        key: certs/orders-client.key
```

## Right

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: paymentsClient
        hosts: [payments.internal.example]
        cert: certs/payments-client.pem
        key: certs/payments-client.key
```
