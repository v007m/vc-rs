When a `type: graphql` api file names its schema in `graphql.schema`, each api's document is checked against it by
the GraphQL spec's validation rules. V2314 is a document the server would reject: a field its type does not have
(the help names the type's fields, and the one close field is the fix), an argument the field needs left out, a
variable of one type passed where the argument takes another (`String` into `ID!`), a selection on a field that
returns a scalar or an enum, or no selection on one that returns an object. The diagnostic points at the part of the
document at fault, in the `.graphql` file or the inline `query`. Without `graphql.schema` none of this is
checked; a schema file that is not one is V1015.

## Wrong

```yaml wrong V2314 title="services/catalog/catalog.api.yaml"
type: graphql
graphql:
  schema: {$file: schema.graphql}
apis:
  - id: getProduct
    body:
      query: "query GetProduct($id: ID!) { product(id: $id) { id nmae } }"
      variables: {id: p1}
```

```graphql wrong V2314 title="services/catalog/schema.graphql"
type Query {
  product(id: ID!): Product
  products(limit: Int): [Product!]
}

type Product {
  id: ID!
  name: String
  price: Int
}
```

## Right

```yaml title="services/catalog/catalog.api.yaml"
type: graphql
graphql:
  schema: {$file: schema.graphql}
apis:
  - id: getProduct
    body:
      query: "query GetProduct($id: ID!) { product(id: $id) { id name } }"
      variables: {id: p1}
```

```graphql title="services/catalog/schema.graphql"
type Query {
  product(id: ID!): Product
  products(limit: Int): [Product!]
}

type Product {
  id: ID!
  name: String
  price: Int
}
```
