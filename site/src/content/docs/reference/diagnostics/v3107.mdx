`vc check` reads each `http.tls.clients` certificate the config writes as text, a `cert` or a `pkcs12` bundle, and
warns when it expires within 30 days, counted in whole days in UTC; on its last day it says "expires today", as the
check sees the day, not the hour. Until then a run presents it as before; once it expires, servers refuse it at the
handshake (V5127). Only the client's own certificate is dated, not the rest of its
chain and not the `ca` roots. A run says the same, in a warning at its end, about each certificate its profiles
present, one whose path or text is rendered from a `${…}` too. Renew it and point `cert` at the new one.

## Wrong

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: paymentsClient
        hosts: [payments.internal.example]
        cert: certs/payments-client-2026.pem
        key: certs/payments-client-2026.key
```

## Right

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: paymentsClient
        hosts: [payments.internal.example]
        cert: certs/payments-client-2027.pem
        key: certs/payments-client-2027.key
```
