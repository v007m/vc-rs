A plugin is a separate program the engine talks to over JSON-RPC. It failed: it crashed, did not answer within its
deadline (5 seconds to start, 30 seconds a call), answered something that is not the protocol, or asked for a secret
its manifest does not declare. Only the work that used the plugin fails. A plugin gets only the secrets that
`vibranium-plugin.yaml` lists under `permissions.secrets` and that `vibranium.lock` approved, so a plugin that needs
another one must declare it, and `vc plugin add` asks you to approve it again. A `path:` plugin whose installed files
changed since `vibranium.lock` approved them is refused the same way on its first call, until `vc plugin add` approves
them again. A plugin must not write into its install folder (`.vibranium/plugins/<id>/`): it keeps its own files in the
folder that `$VIB_PLUGIN_DATA` names (`.vibranium/plugin-data/<id>/`, made on first use). Write state to
`$VIB_PLUGIN_DATA`; re-approve with `vc plugin add` if the change was intended.

## Wrong

```yaml title=".vibranium/plugins/acmeReport/vibranium-plugin.yaml"
id: acmeReport
version: 1.0.0
kind: reporter
entry: {command: python3, args: [report.py]}
permissions: {secrets: [reportToken]}
```

```python title=".vibranium/plugins/acmeReport/report.py"
key = rpc.request("secrets/get", {"name": "apiKey"})
```

## Right

```yaml title=".vibranium/plugins/acmeReport/vibranium-plugin.yaml"
id: acmeReport
version: 1.0.0
kind: reporter
entry: {command: python3, args: [report.py]}
permissions: {secrets: [reportToken]}
```

```python title=".vibranium/plugins/acmeReport/report.py"
token = rpc.request("secrets/get", {"name": "reportToken"})
```
