`reports.dir` in `vibranium.config.yaml`, or the default `.vibranium/reports`, must stay inside the project on disk
too. Before a run writes a report, and before `vc history prune` removes a run folder, `vc` resolves the folder's
nearest part that exists, links followed; when that is outside the project, or cannot be resolved, the run writes no
report files (its tests still run, and their results and exit code are unchanged) and `vc history prune` exits 2
without removing anything. Replace the link with a folder, or point `reports.dir` inside the project. A folder outside
the project is yours to choose with `--out <dir>`, `VIB_REPORTS_DIR` or your user config, and is not checked (D327).

## Wrong

`.vibranium/reports` is a link to a folder outside the project.

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
```

## Right

`.vibranium/reports` is a folder in the project, or `reports.dir` names one.

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
reports:
  dir: reports/ci
```

The same page is built into the binary, so this works anywhere, even outside a project:

