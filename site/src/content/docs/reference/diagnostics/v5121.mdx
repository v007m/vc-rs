`reports.dir` in `vibranium.config.yaml`, a `VIB_REPORTS_DIR` line in the project's `.env`, or the default
`.vibranium/reports`, must stay inside the project on disk too: a `.env` comes with a project you clone, like its
config, so its folder is the project's. Before a run writes a report, and before `vc history prune` removes a run
folder, `vc` resolves the folder's nearest part that exists, links followed; when that is outside the project, or cannot
be resolved, the run writes no report files (its tests still run, and their results and exit code are unchanged) and `vc
history prune` exits 2 without removing anything. Replace the link with a folder, or point `reports.dir`, or the `.env`
line, inside the project. A folder outside the project is yours to choose with `--out <dir>`, `--set reports.dir=<dir>`,
`VIB_REPORTS_DIR` in your environment or your user config, and is not checked (D327).

## Wrong

`.vibranium/reports` is a link to a folder outside the project.

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
```

## Right

`.vibranium/reports` is a folder in the project, or `reports.dir` names one.

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
reports:
  dir: reports/ci
```
