A run writes its report files into `reports.dir`, and `history.keep` and `vc history prune` remove old run folders from
it. In `vibranium.config.yaml` it must name a folder inside the project, written as plain folder names, such as
`reports/ci`: an absolute path (`/tmp/out`, `C:\out`) or a `..` part (`../out`) is refused, so a project you clone
cannot write or prune files elsewhere on your machine. A folder outside the project is yours to choose: pass `--out
<dir>`, `--set reports.dir=<dir>` or `VIB_REPORTS_DIR` in your environment, or set `reports.dir` in your user config
(`~/.config/vibranium/config.yaml`); none of those is checked. A `VIB_REPORTS_DIR` line in the project's `.env` is a
project file too, so it is checked when the run writes: one that leaves the project is V5121. A run also follows links:
a project folder that leads outside the project through one is V5121, and nothing is written there (D327).

## Wrong

```yaml wrong V2313 title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
reports:
  dir: ../ci-reports
```

## Right

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
reports:
  dir: reports/ci
```
