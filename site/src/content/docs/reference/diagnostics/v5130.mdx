A stream call waits at each `receive` item for a message its check matches, skipping the ones that do not. When the
server closes the stream, the connection drops or the call's `timeout` passes while a `receive` is still waiting, the
step fails at that item. The report shows what the item expected and every message received since the last match, so
a field written with the wrong value, or a message the server sends under another `event`, shows up next to it. Here
the server names the event `price`, so a check for `quote` waits until the time runs out.

## Wrong

```yaml title="services/feed/feed.api.yaml"
type: sse
apis:
  - id: prices
    path: /prices
    timeout: 5s
    exchange:
      - receive: {event: quote, data: {match: {symbol: ACME}}}
```

## Right

```yaml title="services/feed/feed.api.yaml"
type: sse
apis:
  - id: prices
    path: /prices
    timeout: 5s
    exchange:
      - receive: {event: price, data: {match: {symbol: ACME}}}
```
