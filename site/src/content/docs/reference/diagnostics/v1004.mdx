The key is not one this place accepts. It is usually a typo, and the diagnostic suggests the closest key with a certain
fix. Keys are checked so that a misspelt setting is reported instead of silently ignored. A matcher map is checked the
same way: a key that is not a matcher's name, next to one that is (`{gt: 0, lenght: 3}`), is V1004, and so is any key
that is not a matcher's name in a status map or `saveOn`, which are never literal objects. Elsewhere a map with no
matcher's name as a key is a literal object; when its one key is close to a matcher's name, that is the warning [V3207](/vc-rs/reference/diagnostics/v3207/).

## Wrong

```yaml wrong title="services/users/users.api.yaml"
nmae: Users
apis: []
```

## Right

```yaml title="services/users/users.api.yaml"
name: Users
apis: []
```

## Seen in practice

This is real output from `vc`, run against the files below.

```yaml wrong title="services/users/users.api.yaml"
id: users
name: Users
baseUrl: http://localhost:7421
apis:
  - id: listUsers
    name: List users
    path: /users
    methd: GET
```

```console
$ vc check
error[V1004]: unknown key `methd` in apiEntry
 --> services/users/users.api.yaml:8:5
  |
8 |     methd: GET
  |     ^^^^^ not a known key
  = help: did you mean `method`?
  = fix: Replace with method (certain)

1 error · 0 warnings · 2 files checked
$ echo $?
2
```

## Explain it in your terminal

The same page is built into the binary, so this works anywhere, even outside a project:

```console
$ vc explain V1004
```
