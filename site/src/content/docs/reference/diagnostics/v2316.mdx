An `awsSigV4` auth's `region` and `service` go into every signature's credential scope, as AWS
writes them: lowercase letters, digits and `-`, such as `us-east-1` and `execute-api`. A literal
value with a capital, a space, an `_` or anything else would sign every request for a scope the
service does not know, so each one would be refused with `403`. Write the region's code and the
service's signing name. When lowercasing the value is enough, that is the certain fix. `vc check`
does not check a value with a `${…}` in it: the signer checks it when it renders, and a value
that breaks the rule fails the call with V5114.

## Wrong

```dotenv wrong V2316 title=".env.schema"
AWS_ACCESS_KEY_ID=
# @sensitive
AWS_SECRET_ACCESS_KEY=
```

```yaml wrong V2316 title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
auth:
  - id: ordersIam
    type: awsSigV4
    region: US-East-1
    service: execute-api
    accessKeyId: ${secret.AWS_ACCESS_KEY_ID}
    secretAccessKey: ${secret.AWS_SECRET_ACCESS_KEY}
```

## Right

```dotenv title=".env.schema"
AWS_ACCESS_KEY_ID=
# @sensitive
AWS_SECRET_ACCESS_KEY=
```

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
auth:
  - id: ordersIam
    type: awsSigV4
    region: us-east-1
    service: execute-api
    accessKeyId: ${secret.AWS_ACCESS_KEY_ID}
    secretAccessKey: ${secret.AWS_SECRET_ACCESS_KEY}
```
