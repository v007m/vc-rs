A call to a `graphql` api with no `saveOn` got a response with `errors`, so its `save` did not run and its `cleanup` was
not registered. An error usually nulls the field it is on: saving `${response.body.data.createUser.id}` would fail at
run time, and a cleanup would fire with a null id. The default `saveOn` therefore needs the status to match and
`errors` to be absent or empty. An explicit `saveOn` is status only, for an api whose saved fields survive its errors.
Here `createUser` returns the new user's id even when sending the welcome email fails.

## Wrong

```yaml title="services/accounts/accounts.api.yaml"
type: graphql
apis:
  - id: createUser
    body:
      query: 'mutation CreateUser($name: String!) { createUser(name: $name) { id welcomeSent } }'
      variables:
        name: Ada
    save:
      userId: ${response.body.data.createUser.id}
```

## Right

```yaml title="services/accounts/accounts.api.yaml"
type: graphql
apis:
  - id: createUser
    body:
      query: 'mutation CreateUser($name: String!) { createUser(name: $name) { id welcomeSent } }'
      variables:
        name: Ada
    save:
      userId: ${response.body.data.createUser.id}
    saveOn: 200
```
