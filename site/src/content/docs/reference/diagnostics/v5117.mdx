An alert rule fired at the end of the run, but its channel could not be reached or refused the message. The run's
results and exit code are unchanged: an alert is a notice about the run, never part of it. The message names the
channel and the HTTP status or the network error, never the webhook URL or a routing key, which are secrets. Check
the channel's settings, and that the secret it reads is set in the profile the run used.

`vc check` gives the same warning before any run for a channel name the engine does not know, and for settings
the channel refuses, such as a missing `webhook` or an unknown PagerDuty `severity`. A setting written as a
`${…}` template is checked only when the run ends.

## Wrong

```yaml title="vibranium.config.yaml"
alerts:
  - on: [failure]
    notify:
      - slack: {channel: "#qa-alerts", webhook: https://hooks.slack.com/services/T000/B000/expired}
```

## Right

```yaml title="vibranium.config.yaml"
alerts:
  - on: [failure]
    notify:
      - slack: {channel: "#qa-alerts", webhook: "${secret.SLACK_WEBHOOK}"}
```
