A call to a `graphql` api got a response with `errors`, and no `expect.errors` check failed on them. GraphQL errors
pass by default, so the step keeps its verdict, and this warning lists each error as `CODE at path: message` so that a
tolerated error stays visible. The warning is a note, not a failure: when the errors are part of the behaviour under
test, pin them with `expect.errors`, so that a different error fails the step; when they should not happen,
`errors: none` fails the step on them. Here the server hides `secretNote` with a `FORBIDDEN` error that the test does
not check.

## Wrong

```yaml title="services/accounts/accounts.api.yaml"
type: graphql
apis:
  - id: getSecretNote
    body:
      query: 'query GetSecretNote($id: ID!) { user(id: $id) { name secretNote } }'
      variables:
        id: "2"
```

```yaml title="services/accounts/privacy.test.yaml"
tests:
  - id: hidesSecretNote
    call: accounts#getSecretNote
    expect:
      body:
        match:
          data.user.secretNote: null
```

## Right

```yaml title="services/accounts/accounts.api.yaml"
type: graphql
apis:
  - id: getSecretNote
    body:
      query: 'query GetSecretNote($id: ID!) { user(id: $id) { name secretNote } }'
      variables:
        id: "2"
```

```yaml title="services/accounts/privacy.test.yaml"
tests:
  - id: hidesSecretNote
    call: accounts#getSecretNote
    expect:
      errors: [{code: FORBIDDEN, path: user.secretNote}]
      body:
        match:
          data.user.secretNote: null
```
