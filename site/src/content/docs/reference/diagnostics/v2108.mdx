An operation declares its variables, such as `query GetProduct($id: ID!)`. A variable whose type ends in `!` and that
has no default must get a value, so `body.variables` must give it one; the server refuses the request otherwise. A
value for a variable the operation does not declare is a mistake too, most often a misspelt name, and the fix is the
declared name when one is close. `variables` written as one template, such as `${var.filters}`, is not checked, since
its keys are known only when the test runs.

## Wrong

```yaml wrong V2108 title="services/catalog/catalog.api.yaml"
type: graphql
apis:
  - id: getProduct
    body:
      query: 'query GetProduct($id: ID!) { product(id: $id) { id name } }'
      variables: {productId: p1}
```

## Right

```yaml title="services/catalog/catalog.api.yaml"
type: graphql
apis:
  - id: getProduct
    body:
      query: 'query GetProduct($id: ID!) { product(id: $id) { id name } }'
      variables: {id: p1}
```
