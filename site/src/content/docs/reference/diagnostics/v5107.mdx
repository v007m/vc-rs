An api's `cleanup` ran after a successful call and failed. It is a warning: the test's result stays as it was, but the
data it made may be left behind. A cleanup that deletes should accept "already gone" too, since a test may have
deleted the item itself.

## Wrong

```yaml wrong title="services/users/users.api.yaml"
apis:
  - id: createUser
    method: POST
    path: /users
    body:
      name: Ada
    expect:
      status: 201
    cleanup:
      call: deleteUser
      vars:
        userId: ${response.body.id}
  - id: deleteUser
    method: DELETE
    path: /users/${var.userId}
    vars:
      userId: 0
    expect:
      status: 204
```

## Right

```yaml title="services/users/users.api.yaml"
apis:
  - id: createUser
    method: POST
    path: /users
    body:
      name: Ada
    expect:
      status: 201
    cleanup:
      call: deleteUser
      vars:
        userId: ${response.body.id}
  - id: deleteUser
    method: DELETE
    path: /users/${var.userId}
    vars:
      userId: 0
    expect:
      status: [204, 404]
```
