A check in `expect` did not hold for the response: a status, header, body match, schema or timing. The report shows
the expected and the actual value side by side. Here the service answers `201 Created`, but the test expects `200`; a
test's `status` replaces the api's.

## Wrong

```yaml title="services/users/users.api.yaml"
apis:
  - id: createUser
    method: POST
    path: /users
    body:
      name: Ada
```

```yaml title="services/users/crud.test.yaml"
tests:
  - id: createsUser
    call: users#createUser
    expect:
      status: 200
```

## Right

```yaml title="services/users/users.api.yaml"
apis:
  - id: createUser
    method: POST
    path: /users
    body:
      name: Ada
```

```yaml title="services/users/crud.test.yaml"
tests:
  - id: createsUser
    call: users#createUser
    expect:
      status: 201
```

## Seen in practice

This is real output from `vc`, run against the files below.

```yaml title="services/users/crud.test.yaml"
id: users.crud
name: Users CRUD
tests:
  - id: listsUsers
    name: Lists users
    call: users#listUsers
    expect:
      status: 201
  - id: countsUsers
    name: Counts users
    call: users#listUsers
    expect:
      cel:
        returns users: response.body.users.size() > 0
```
