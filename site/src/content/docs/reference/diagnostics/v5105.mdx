The request never got a response: the host name did not resolve, the connection was refused or reset, or TLS failed.
A status code, even 500, is never a transport error. Check the base URL the active profile gives (`vc explain
<apiId>` shows the final URL) and that the service is running.

## Wrong

```yaml wrong title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
vars:
  usersUrl: http://localhost:9
```

```yaml wrong title="services/users/users.api.yaml"
baseUrl: ${var.usersUrl}
apis:
  - id: listUsers
    path: /users
```

## Right

```yaml title="vibranium.config.yaml"
syntaxVersion: 2
profiles:
  - id: dev
    default: true
vars:
  usersUrl: http://localhost:7421
```

```yaml title="services/users/users.api.yaml"
baseUrl: ${var.usersUrl}
apis:
  - id: listUsers
    path: /users
```

## Seen in practice

This is real output from `vc`, run against the files below.

```yaml wrong title="services/users/users.api.yaml"
id: users
name: Users
baseUrl: http://localhost:7499
apis:
  - id: listUsers
    name: List users
    path: /users
```

```yaml wrong title="services/users/crud.test.yaml"
id: users.crud
name: Users CRUD
tests:
  - id: listsUsers
    name: Lists users
    call: users#listUsers
```

```console
$ vc run
plan  1 test in 1 file · profile default

✕ users.crud#listsUsers                                           1ms
  error[V5105]: cannot connect to localhost:7499: Connection refused (os error 61)
     = at: call users#listUsers

0 passed · 1 failed                                          2ms · profile default
$ echo $?
1
```
