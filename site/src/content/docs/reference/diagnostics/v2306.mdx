A matcher's argument is not one it accepts: an unknown `type`, a `regex` that does not compile, or a `between` without
exactly two values. The diagnostic says what the matcher needs.

## Wrong

```yaml wrong title="services/users/users.api.yaml"
apis:
  - id: getUser
    path: /users/1
```

```yaml wrong title="services/users/crud.test.yaml"
tests:
  - id: getsUser
    call: users#getUser
    expect:
      body:
        match:
          id: {type: strng}
```

## Right

```yaml title="services/users/users.api.yaml"
apis:
  - id: getUser
    path: /users/1
```

```yaml title="services/users/crud.test.yaml"
tests:
  - id: getsUser
    call: users#getUser
    expect:
      body:
        match:
          id: {type: string}
```

## Seen in practice

This is real output from `vc`, run against the files below.

```yaml wrong title="services/users/crud.test.yaml"
id: users.crud
name: Users CRUD
tests:
  - id: listsUsers
    name: Lists users
    call: users#listUsers
    expect:
      body:
        match:
          id: {type: strng}
```

```console
$ vc check
error[V2306]: `type` does not know `strng`
  --> services/users/crud.test.yaml:10:22
   |
10 |           id: {type: strng}
   |                      ^^^^^
   = help: did you mean `string`?
   = fix: Replace with string (certain)

1 error · 0 warnings · 3 files checked
$ echo $?
2
```
