A stream call opened no stream it can read: an `sse` answer that is not 2xx or whose `content-type` is not
`text/event-stream`, or a `websocket` handshake answered with a status other than `101`. The step fails at its first
`receive` (at the step when it has none), naming the status or the content type, and the opening response stays
checkable through `status`, `headers` and `body`. This usually means a wrong `path`, such as a JSON route answering
where the event stream should be, or auth the server refused.

## Wrong

```yaml title="services/feed/feed.api.yaml"
type: sse
apis:
  - id: prices
    path: /prices.json
    exchange:
      - receive: {event: price}
```

## Right

```yaml title="services/feed/feed.api.yaml"
type: sse
apis:
  - id: prices
    path: /prices/stream
    exchange:
      - receive: {event: price}
```
