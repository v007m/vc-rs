This section covers the two ways `vc` reaches outside itself: **plugins**, which are programs you add to a project, and **alerts**, which send a message when a run ends.

```yaml title="vibranium.config.yaml"
plugins:
  - id: summary
    source: path:plugins/summary

reports:
  formats: [ctrf, summary]       # run the reporter plugin after each run

alerts:
  - on: [failure, recovery]
    notify:
      - slack:
          webhook: ${secret.slackWebhook}
          channel: "#qa-alerts"
```

## Plugins

A plugin is a separate program, written in any language, that `vc` starts and talks to over stdin and stdout with JSON-RPC. Two kinds are in use today:

| Kind | What it does | How a project uses it |
| --- | --- | --- |
| `reporter` | Gets every run event and writes report files | Its ID goes in `reports.formats` |
| `auth` | Returns headers, query values or cookies for a request | An auth definition with `type: plugin` names it |

A manifest may also say `importer` or `executor`. `vc` accepts those kinds, but has no methods for them yet, so they do nothing.

You install a plugin with `vc plugin add`. It shows what the plugin asks to reach and records your approval in `vibranium.lock`, which you commit. A run refuses a plugin that asks for more than the lock grants.

## Alerts

An alert rule picks which runs to tell someone about, and where to send the message. `vc run` and `vc load` send alerts once the run ends and its reports are written. A failed alert is a warning (V5117); it never changes the exit code.

| Channel | Sends |
| --- | --- |
| `webhook` | The run's CTRF summary as JSON, with the alert under `results.extra` |
| `slack` | A Slack Block Kit message to an incoming webhook |
| `teams` | An Adaptive Card 1.4 to a Teams incoming webhook |
| `pagerduty` | A PagerDuty Events API v2 event, resolved again on recovery |

<Aside type="caution" title="No email channel">
Some older design notes list an `email` channel. It does not exist yet. `vc check` warns that there is no alert channel named `email` (V5117), and a run sends nothing to it.
</Aside>
