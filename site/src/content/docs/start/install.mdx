Vibranium is one binary, `vc`. A second small binary, `vc-demo`, is the demo service that the [quickstart](/vc-rs/start/quickstart/) and the `vc init` sample call.

## Homebrew

On macOS and Linux, install from the project's tap:

<InstallCommand method="brew" />

<Aside title="Why --HEAD">
There is no tagged release yet, so the formula builds the latest `master`. Once v0.1.0 is tagged the command drops `--HEAD`. `brew upgrade --fetch-HEAD vibranium` rebuilds it from the newest commit.
</Aside>

## Cargo

Without Homebrew, build with Cargo. You need Rust 1.99 or later. If you use [rustup](https://rustup.rs), the repo's `rust-toolchain.toml` picks the right toolchain for you when you build inside a clone.

<Tabs>
  <TabItem label="Straight from Git">
    <InstallCommand method="cargo" />

    This uses your default toolchain, so make sure `rustc --version` is 1.99 or later.
  </TabItem>
  <TabItem label="From a clone">
    <Steps>
    1. Clone the repo.

       ```console
       git clone https://github.com/v007m/vc-rs
       cd vc-rs
       ```

    2. Install `vc` and `vc-demo` into `~/.cargo/bin`.

       ```console
       cargo install --path crates/apps/cli --locked
       cargo install --path crates/apps/demo --locked
       ```
    </Steps>
  </TabItem>
</Tabs>

Install both packages. `vc demo start` looks for `vc-demo` in the folder `vc` is in, then on your `PATH`. Without it you get:

```console
$ vc demo start
error: `vc-demo` is not next to vc (in /home/me/.cargo/bin) or on PATH
  = help: install it with `cargo install --git https://github.com/v007m/vc-rs vc-demo --locked`, or put `vc-demo` next to `vc`
```

## Check the install

```console
$ vc --version
vc 0.1.0
```

## The `vibranium` name

The full name of the command is `vibranium`, and `vc` is the short form. Both install methods give you both names:

- **Homebrew** links `vibranium` to `vc` in the same folder.
- **Cargo**: `vc-cli` installs `vibranium` as a tiny launcher that runs the `vc` in its own folder.

Either way, `vibranium` still works when another tool's `vc` comes first on your `PATH` (the Vercel CLI has one, for example) or a shell aliases it:

```console
$ vibranium --version
vc 0.1.0
```

The Cargo launcher looks for `vc` only in the folder of its real file, after following any link to it, and never on your `PATH`, so it can't run another tool's `vc`. If `vc` isn't in that folder, it exits 2:

```console
$ vibranium --version
error: `vibranium` runs the `vc` next to it, and cannot: there is no `vc` in /home/me/bin
  = help: install both with `cargo install --git https://github.com/v007m/vc-rs vc-cli vc-demo --locked`
```

Every example in these docs uses `vc`. Swap in `vibranium` if you need to.

## Shell completion

`vc completion <shell>` prints a completion script for `bash`, `zsh`, `fish` or `powershell`. Besides commands and flags, it completes the IDs in your project: test IDs after `vc run`, api IDs after `vc call`, profile names after `--profile` and tags after `-t`.

<Tabs>
  <TabItem label="zsh">
    ```console
    vc completion zsh > ~/.zfunc/_vc
    ```

    Make sure `~/.zfunc` is on your `fpath` before `compinit` runs, in `~/.zshrc`:

    ```console
    fpath=(~/.zfunc $fpath)
    autoload -Uz compinit && compinit
    ```
  </TabItem>
  <TabItem label="bash">
    ```console
    vc completion bash > ~/.local/share/bash-completion/completions/vc
    ln -s vc ~/.local/share/bash-completion/completions/vibranium
    ```
  </TabItem>
  <TabItem label="fish">
    ```console
    vc completion fish > ~/.config/fish/completions/vc.fish
    ln -s vc.fish ~/.config/fish/completions/vibranium.fish
    ```
  </TabItem>
  <TabItem label="PowerShell">
    ```console
    vc completion powershell >> $PROFILE
    ```
  </TabItem>
</Tabs>

<Aside>
The scripts complete both names, `vc` and `vibranium`. bash and fish load a completion file by the command's name, so the link lets `vibranium` find the same script.
</Aside>

ID completion reads your project, so open a new shell inside a project folder and try `vc run sample.<Tab>`.
