AI agents

2 agents connected 2 waiting for you

Coding agents such as Claude Code or Cursor can work with this project through MCP, the protocol they use for tools. Once connected, an agent can find and run tests, explain why one failed, call your apis and edit test files, using the same project files and profiles you do.

Access per profileEach profile says what agents may run, call and edit. prod is read-only. ApprovalsAnything risky pauses the agent until you approve it here. RedactionSecrets and tokens are replaced with [redacted] in everything an agent sees. A full logEvery call is kept in the project history with its arguments and result.

Connect an agent

Once per project. The agent starts Vibranium’s MCP server when it needs it.

Add this to .cursor/mcp.json in the project. For Windsurf, add it to ~/.codeium/windsurf/mcp_config.json.

1{2  "mcpServers": {3    "vibranium": {4      "command": "vc",5      "args": ["mcp"]6    }7  }8}
Connected: Cursor· 12 min ago · Windsurf last seen 13:52
Then try asking it: “Which tests failed in the last staging run, and why?”
What a connected agent can do
list_definitionsLists apis, tests, load files and profiles with their ids and files.
searchFinds tests and apis by id, name, tag, path or text.
checkValidates the project like vc check and returns the diagnostics.
run_testsRuns tests by id, file or tag and returns results and the report path. · asks you on staging, prod
explain_failureExplains a failed test: expected vs actual, history and related commits.
read_historyReads past runs, flaky tests and timings from history.
call_apiSends one api call with a profile’s vars and auth; secrets stay hidden. · asks you on staging, prod
write_definitionCreates or edits test and api files; checked before saving. · asks you on staging · off on prod

What agents may do

Per profile, from profiles[].agents in vibranium.config.yaml. Agents use the profile you picked when you connected them, or the one they ask for.

dev

Run tests Any test
Call apis without asking Any method
Asks you first Nothing
Edit test and api files Yes

staging

selected profile
Run tests Tests that send only GET or POST; others ask you
Call apis without asking GETPOST
Asks you first PUTPATCHDELETE
Edit test and api files Yes, after you approve each change

prod

Run tests Read-only tests; a test that sends anything else asks you
Call apis without asking GET
Asks you first POSTPUTPATCHDELETE
Edit test and api files No
