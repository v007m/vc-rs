# V3208: A literal object whose one key is close to a matcher's name

A map whose keys are not matcher names is a literal object that the value must equal. When it has one key that is a
single edit or so from a matcher's name (`startWith`, `lenght`, `Length`, `exist`), it is still compared as that
literal, but it is far more likely a misspelt matcher. Fix the name to use the matcher, or put the object under `eq:` to
say it is meant as a literal. A status map is never a literal, so an unknown key there is V1004 instead.

## Wrong

```yaml
# file: services/users/users.api.yaml
apis:
  - id: getUser
    path: /users/1
```

```yaml
# file: services/users/crud.test.yaml
tests:
  - id: getsUser
    call: users#getUser
    expect:
      body:
        name: {startWith: A}
```

## Right

```yaml
# file: services/users/users.api.yaml
apis:
  - id: getUser
    path: /users/1
```

```yaml
# file: services/users/crud.test.yaml
tests:
  - id: getsUser
    call: users#getUser
    expect:
      body:
        name: {startsWith: A}
```
