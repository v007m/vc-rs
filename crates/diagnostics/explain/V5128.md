# V5128: The response has GraphQL errors

A call to a `graphql` api got a response with `errors`, and the step has no `expect.errors` check. GraphQL errors
pass by default, so the step keeps its verdict, and this warning lists each error as `CODE at path: message` so that an
error nobody asserted stays visible. When the errors are part of the behaviour under test, pin them with
`expect.errors`: a passing check is silent, and a different error fails the step (V5123). When they should not happen,
`errors: none` fails the step on them. Here the server hides `secretNote` with a `FORBIDDEN` error that the test does
not check.

## Wrong

```yaml
# file: services/accounts/accounts.api.yaml
type: graphql
apis:
  - id: getSecretNote
    body:
      query: 'query GetSecretNote($id: ID!) { user(id: $id) { name secretNote } }'
      variables:
        id: "2"
```

```yaml
# file: services/accounts/privacy.test.yaml
tests:
  - id: hidesSecretNote
    call: accounts#getSecretNote
    expect:
      body:
        match:
          data.user.secretNote: null
```

## Right

```yaml
# file: services/accounts/accounts.api.yaml
type: graphql
apis:
  - id: getSecretNote
    body:
      query: 'query GetSecretNote($id: ID!) { user(id: $id) { name secretNote } }'
      variables:
        id: "2"
```

```yaml
# file: services/accounts/privacy.test.yaml
tests:
  - id: hidesSecretNote
    call: accounts#getSecretNote
    expect:
      errors: [{code: FORBIDDEN, path: user.secretNote}]
      body:
        match:
          data.user.secretNote: null
```
