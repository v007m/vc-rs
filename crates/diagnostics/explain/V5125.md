# V5125: A client certificate or trusted root cannot be read

When a run starts, it reads the `http.tls` material its profiles use: each `ca` root, and the `cert` and `key`, or
`pkcs12` bundle, of every `clients` entry active under the run's profiles. A file that is missing, cannot be opened, is
not a regular file (a FIFO, a device, a folder) or is over 1 MiB, or text that is not a PEM certificate, a PEM private key or a PKCS#12 bundle, stops the run before any
request, with exit code 2. An encrypted PEM key is refused too; give the key unencrypted, through a secret, or use a
PKCS#12 bundle with a passphrase. The message names the entry and its key (`cert`, `key`, `pkcs12`), and the file
only when the config wrote its path as text, never the key or a value a template rendered. A relative path is read
from the project root. Here `key` names a file that is not there.

## Wrong

```yaml
# file: vibranium.config.yaml
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: paymentsClient
        hosts: [payments.internal.example]
        cert: certs/payments-client.pem
        key: certs/payments-clinet.key
```

## Right

```yaml
# file: vibranium.config.yaml
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: paymentsClient
        hosts: [payments.internal.example]
        cert: certs/payments-client.pem
        key: certs/payments-client.key
```
