# V3107: A client certificate expires within 30 days

`vc check` reads each `http.tls.clients` certificate the config writes as text, a `cert` or a `pkcs12` bundle, and
warns when it expires within 30 days, counted in whole days in UTC. Until then a run presents it as before; once it
expires, servers refuse it at the handshake (V5127). Only the client's own certificate is dated, not the rest of its
chain and not the `ca` roots. Renew it and point `cert` at the new one.

## Wrong

```yaml
# file: vibranium.config.yaml
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: paymentsClient
        hosts: [payments.internal.example]
        cert: certs/payments-client-2026.pem
        key: certs/payments-client-2026.key
```

## Right

```yaml
# file: vibranium.config.yaml
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: paymentsClient
        hosts: [payments.internal.example]
        cert: certs/payments-client-2027.pem
        key: certs/payments-client-2027.key
```
