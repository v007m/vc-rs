# V5119: A plugin cannot be confined to its permissions

A plugin's process runs held to the permissions in its manifest. On macOS that is `sandbox-exec`, and a plugin
that it cannot start under (for example when `vc` itself runs in a sandbox) is not started at all, so only the work
that uses the plugin fails. When you trust the plugin, you may run it unconfined: set `plugins.allowUnconfined: true`
in your user config (`~/.config/vibranium/config.yaml`), or `VIB_PLUGINS_ALLOW_UNCONFINED=1` in the environment. The
setting is never read from `vibranium.config.yaml`, a profile or `.env`, so a project you clone cannot switch
confinement off. A plugin that runs unconfined (this opt-out, or Linux without Landlock) prints one warning per run
naming it, and the run's report records it.

## Wrong

`vc` runs inside a sandbox, so `acmeAuth` cannot start confined and the calls that use it fail with V5119. Switching
confinement off in the project has no effect: `plugins` there is the list of plugins, not a setting.

```yaml
# file: vibranium.config.yaml
plugins:
  - id: acmeAuth
    source: path:./plugins/acme-auth
```

## Right

```yaml
# file: ~/.config/vibranium/config.yaml
plugins:
  allowUnconfined: true
```
