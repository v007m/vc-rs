# V4013: A client key or passphrase is written in the config

An `http.tls.clients` entry holds its private key as inline PEM, or its PKCS#12 `passphrase` as text, so the
secret is committed to git with `vibranium.config.yaml`. Read it with `${secret.NAME}` instead and declare the name
in `.env.schema`: the value then comes from `.env` (or the secrets provider) and is masked in every output. A path
to a key file is fine; keep the file out of git.

## Wrong

```yaml
# file: vibranium.config.yaml
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: partnerCert
        pkcs12: certs/partner.p12
        passphrase: hunter2
```

## Right

```dotenv
# file: .env.schema
# @sensitive
PARTNER_P12_PASSPHRASE=
```

```yaml
# file: vibranium.config.yaml
syntaxVersion: 2
profiles:
  - id: dev
    default: true
http:
  tls:
    clients:
      - id: partnerCert
        pkcs12: certs/partner.p12
        passphrase: ${secret.PARTNER_P12_PASSPHRASE}
```
