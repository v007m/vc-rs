# V2213: A key that does not apply to the api's `type`

An api's `type` decides which keys it takes: on the api item, in an `expect`, and on a test or step that calls it.
A key that the type does not use is an error, since it would be ignored. The fix removes it.

The same holds for a key a test with `steps` hands its `call` steps, such as `body`, when a step without its
own calls an api whose type does not take it. Other steps may still send it, so that one has no fix: move the key
onto the steps that send it. A `graphql` api's `body` takes only `query`, `variables` and `operationName`; the fix
for another key is the close one. A `graphql` block is read only on a `type: graphql` file; elsewhere the fix
removes it.

`http`, the default type, takes every key, so no `http` api reports this code. It applies once an api sets a
type that leaves keys out, such as `graphql`, where every request is a `POST` and `method` has no meaning.

## Wrong

```yaml
# file: services/catalog/catalog.api.yaml
type: graphql
apis:
  - id: listProducts
    method: POST
    body:
      query: '{ products { id name } }'
```

## Right

```yaml
# file: services/catalog/catalog.api.yaml
type: graphql
apis:
  - id: listProducts
    body:
      query: '{ products { id name } }'
```
