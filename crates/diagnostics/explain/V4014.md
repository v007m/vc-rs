# V4014: An AWS secret access key or session token is written in the config

An `awsSigV4` auth holds its `secretAccessKey` or `sessionToken` as text, so the credential is
committed to git with `vibranium.config.yaml`. Read it with `${secret.NAME}` instead and declare
the name in `.env.schema`: the value then comes from the environment, `.env` or the secrets
provider, and is masked in every output. With the default provider, the names AWS tools export
(`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`) are read as they are.

## Wrong

```yaml
# file: vibranium.config.yaml
syntaxVersion: 2
profiles:
  - id: dev
    default: true
auth:
  - id: ordersIam
    type: awsSigV4
    region: us-east-1
    service: execute-api
    accessKeyId: AKIAIOSFODNN7EXAMPLE
    secretAccessKey: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
```

## Right

```dotenv
# file: .env.schema
AWS_ACCESS_KEY_ID=
# @sensitive
AWS_SECRET_ACCESS_KEY=
```

```yaml
# file: vibranium.config.yaml
syntaxVersion: 2
profiles:
  - id: dev
    default: true
auth:
  - id: ordersIam
    type: awsSigV4
    region: us-east-1
    service: execute-api
    accessKeyId: ${secret.AWS_ACCESS_KEY_ID}
    secretAccessKey: ${secret.AWS_SECRET_ACCESS_KEY}
```
