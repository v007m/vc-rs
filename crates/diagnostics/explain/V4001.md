# V4001: Test ID breaks the convention

A test ID describes the behaviour in the third person, in camelCase, with the subject implied: `getsUser`,
`rejectsDeclinedCard`. An imperative or a noun (`getUser`, `userTest`) reads badly in reports. `vc check --fix`
renames the test from its `name` and updates every reference. A test with no usable `name` gets its ID with the first
word conjugated (`getUser` becomes `getsUser`); that is a guess, so the fix asks first. The first word ends at a capital
or a digit (`waits2` starts with `waits`), and a leading `should` is dropped (`shouldRejectCard` becomes `rejectsCard`).

## Wrong

```yaml
# file: services/users/users.api.yaml
apis:
  - id: getUser
    path: /users/1
```

```yaml
# file: services/users/crud.test.yaml
tests:
  - id: getUser
    call: users#getUser
```

## Right

```yaml
# file: services/users/users.api.yaml
apis:
  - id: getUser
    path: /users/1
```

```yaml
# file: services/users/crud.test.yaml
tests:
  - id: getsUser
    call: users#getUser
```
