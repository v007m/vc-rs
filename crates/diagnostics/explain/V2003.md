# V2003: Unknown api or test

A `call`, `test` or `cleanup.call` names an api or test that does not exist. Another file's items are referred to by
their full ID, `fileId#id`; the diagnostic suggests the closest ID of the right kind, same-file IDs first. The file ID
and the part after `#` are measured apart: within the named file, or a file ID one typo away, only the part after `#`
is compared, so `people#nah` is not a typo of `people#echo` and `peolpe#getPerson` points only at `people#getPerson`.
The named file is looked up across the whole project, so from `users.crud`, `users.admin#getsUser` points at
`users.admin#getsUsers`, not `users.crud#getsUser`. When nothing in the named file is close, a close ID in another file
is offered in `help:` without a fix, since taking it would change which service is called. With several close IDs it
lists them in `help:` and offers no fix.

## Wrong

```yaml
# file: services/users/users.api.yaml
apis:
  - id: getUser
    path: /users/1
```

```yaml
# file: services/users/crud.test.yaml
tests:
  - id: getsUser
    call: users#getUsr
```

## Right

```yaml
# file: services/users/users.api.yaml
apis:
  - id: getUser
    path: /users/1
```

```yaml
# file: services/users/crud.test.yaml
tests:
  - id: getsUser
    call: users#getUser
```
