# V5108: A dynamically saved value is used but not declared in `provides`

A `function:` or `test:` action saved a value that a later template uses, but the action does not list it in
`provides`. `vc check` cannot see inside such an action, so it relies on `provides` to know what the action sets;
declare every name that later templates read. A `test:` action that `vc check` resolves already declares what the
reused test is seen to save (its `save`, its api's `save`, its steps' saves), so the warning there means a name the
compiler could not see, such as one a `function:` step inside it returns (D282). Here the hook saves `userId`, which
the api's path reads in place of its default.

## Wrong

```yaml
# file: services/users/users.api.yaml
apis:
  - id: getUser
    path: /users/${var.userId}
    vars:
      userId: 0
```

```yaml
# file: services/users/crud.test.yaml
tests:
  - id: getsSeededUser
    before:
      - function: hooks/seed.ts#seedUser
        provides: [userEmail]
    call: users#getUser
```

## Right

```yaml
# file: services/users/users.api.yaml
apis:
  - id: getUser
    path: /users/${var.userId}
    vars:
      userId: 0
```

```yaml
# file: services/users/crud.test.yaml
tests:
  - id: getsSeededUser
    before:
      - function: hooks/seed.ts#seedUser
        provides: [userId, userEmail]
    call: users#getUser
```
